# Claude Code 删光开发者整个 C 盘：跳过权限确认的代价与自动模式之争

- **收藏日期**: 2026-10-13
- **来源**: 微信公众号「CSDN」（整理：郑丽媛）
- **分类**: 事件与评论 / AI Agent 安全
- **原文链接**: https://mp.weixin.qq.com/s/e1n8cVScl_RWbN5-h3x_Gg
- **参考**: https://madrobot.blog/2026/10/07/claude-opus-5-5-deleted-c-drive-claude-code-auto-mode-boris-cherny/ ；https://x.com/PerceptualPeak/status/2107621483392446572

## 概述

开发者 Zac 在 X 上称，他让 Claude Code（Opus 5.5）无人值守自主执行任务，结果整个 C 盘被删除，帖子浏览量超 100 万。他靠每日自动备份到群晖 NAS 恢复了约 98% 数据。Claude Code 负责人 Boris Cherny 回应：这正是推荐使用自动模式（Auto Mode）的原因。

## 关键内容

1. **事故经过**
   - Zac 习惯让 Claude Code 连续跑数小时，为免频繁停下等授权，使用 `--dangerously-skip-permissions` 跳过所有权限确认；自 Opus 4.6 起一直这样用，此前没出事。
   - 他怀疑是一次"PowerShell 语法拼接错误"导致删除波及整个 C 盘。
   - 未公开完整命令日志或截图，无法确认是模型、脚本语法还是其他环节的问题。
   - Zac 承认主要责任在自己（"AI 世界的西部荒野"），但认为防止整盘被清空的基础保护不应完全依赖用户自行配置。

2. **Anthropic 的回应：自动模式**
   - Boris Cherny：自动模式会在执行前做风险判断，拦截不可逆、破坏性或操作当前环境之外资源的行为，这次"几乎肯定会被拦截"。
   - 自 2026-08-14 起，自动模式是 Claude Code Pro/Max/Team 用户的默认权限模式；工具调用交给专门分类器检查，被拦截后 Claude 会找更安全的做法或请求批准。
   - 内部测试（1053 名付费测试者）：人类仅识别拦截 13.6% 的危险命令，自动模式拦截 89%。
   - 约 25% 的交互式 Claude Code 会话启动时选择完全跳过权限确认。
   - Zac 的反驳：自动模式下任务常被中断，像一直在"带孩子"。

3. **网友争论**
   - Windows/PowerShell 派：管道机制复杂、命令串联，LLM 生成的路径斜杠等符号易出错，一旦链中含删除就可能失控。
   - 项目隔离派：是否为项目建专用目录、正确指定工作目录？
   - 能力派：有人数十亿 Token 用了 6 个月从未遇到删根目录。
   - **反例**：一名 Linux 用户上周在**开启自动模式**下仍丢了主目录和另一块硬盘数据——原因是 Claude Code 给项目的文件系统代码写了有问题的测试；靠完整备份和 dotfiles 恢复。说明问题不限于 Windows，自动模式也非万无一失。
   - Anthropic 官方文档也提醒：自动模式降低但不消除风险，建议在隔离环境中运行 Agent。
   - 对照案例：有人让 AI 清理 C 盘，成功释放 65GB 无用数据（遗忘文件、已卸载程序的残留缓存）。

## 影响 / 备注

- 教训清单：① 不要在主力机上用 `--dangerously-skip-permissions` 长时间无人值守；② 优先自动模式，但别当成保险；③ 在容器/VM/专用目录等隔离环境跑 Agent；④ 每日自动备份（含 NAS/异地）是最后防线；⑤ 涉及文件系统删除的测试代码要特别审查。
- 事故细节仅来自当事人自述，未经独立核实。
