## 概述

Felix Rieseberg 负责 Claude.ai、Cowork、Claude Code Desktop 的工程开发。他宣布自己团队的招聘流程不再使用传统编程面试：「至少对我在 Anthropic 的团队来说，编程面试已经死了」。原因是 Claude 已能轻松通过这类测试，面试结果也预测不了工程师在实际工作中能否成功。文章同时给缺乏资历、人脉和话语权的工程师提出建议，核心观点是 **进取心比资历更重要**。

## 为什么取消编程面试

- 以前，小型编程挑战能看出候选人定义问题、找巧妙解法的能力，对判断能否在团队中成功有一定参考价值
- 现在让候选人做一个小型 React 题，就像考汇编语言一样没有意义，因为 Claude 两样都做得更好
- 团队里创造价值最多的工程师，成功的原因与是否擅长这类测试无关
- 他观察到一些入行不久的工程师在借助 AI 后迅速超过了经验更多、编程更强的人。能创造多少价值，不再那么受限于积累了多少年的框架和类库知识

## 新人的优势：「天真」

- Stripe 的 Patrick Collison 叮嘱新人留意让自己觉得奇怪的事，因为老员工早已习以为常
- James March（1991）：组织需要「不断引入天真无知的人」
- 奥逊·威尔斯：「无知，纯粹的无知……只有当你真正了解一个行业时，你才会变得胆怯。」
- Notion 离线模式：大家都把「离线模式不可能实现」当成常识，从没人验证过。作者作为新人直接提了出来
- Notion 大屏电视：作者当年推不动就放弃了。一年后新人 Ji Pei 提前找相关人员谈好，第二天电视就到位了。作者自己在那一年里也变成了「习以为常的老员工」
- 问题在于新人没有话语权。执行成本高的时候，必须先积累人脉和地位，组织才愿意押注你的想法。现在执行成本已经不高了

## 五条建议

1. **业务价值优先于积压工作**：Patrick McKenzie（2011）说「雇用工程师是为了创造商业价值，而不是为了编写程序」。先搞清公司、部门的目标，可以从直属上级的上级在追求什么目标入手
2. **提出大胆的想法**：选那些一旦实现就能显著提高组织达成目标概率的点子
3. **用一个周末做出来**：跳过 PRD、争取支持、排设计和产品资源这些环节，直接拿出能运行的原型
4. **只做一个好点子**：初级工程师常把多个想法塞进一个原型，结果 20 个烂点子盖住了 3 个好点子。原型的作用是把一个想法讲清楚，同时证明你有能力把它做下去
5. **发挥新人视角**：做面向用户的工作，你更能共情用户；做基础设施或开发工具，你还没被灌输「为什么不可能」的理由

## 案例：Claude Code 图形界面

Anthropic 内部原本习惯通过 CLI 使用 Claude Code。入职不久的两位工程师 Anthony Morris 和 Alice Zhao 用一个周末做出了可运行的原型，约 8 天后第一个公开版本就发布了，现在这个图形界面已经是很受欢迎的产品。

## 作者现在怎么招人

他说自己还没有找到完美的方案。筛选简历和作品集时，他会特别留意能体现**审美判断力、共情能力、原则性思维**的小型原型作品。
