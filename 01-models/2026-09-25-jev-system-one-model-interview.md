## 背景

TypeSafe AI 创始人 **Diogo Almeida** 是 OpenAI 核心研究员，InstructGPT 和 **RLHF（人类反馈强化学习）** 的关键技术作者之一，亲手拉开了 ChatGPT 时代的序幕。2026年9月15日，他在静默两年后发布了 **Jev**——一个完全切掉文本生成能力的"系统 1 模型"，专门向程序输出带精确概率和置信度的决策判断。发布后几天，他做客硅谷知名播客 **Latent Space**（主持人 Swyx），完整阐述了技术路线。

## 核心主张

### 1. AI 应该像数据库，不是像同事

> "工程师需要的不是坐在屏幕对面唠嗑的'数字同事'，而是像数据库一样确定、令行禁止、可以直接喂给程序 if 或 switch 语句的底层决策。"

传统 LLM 被训练成会客套聊天、会拒绝执行。Jev 的设计原则：**以代码作为唯一消费者**。输出直接是结构化决策（带概率和置信度），不被终端用户输入干扰。

### 2. 安全拒答在底层 API 中是工程灾难

> "如果将模型作为底层依赖库部署在后台系统中，一旦它毫无征兆地拒绝执行，整个软件系统难道要因为终端用户输入了一句略带敏感词汇的内容，就毫无预警地抛出异常甚至崩溃吗？"

Diogo 区分了两种对齐：
- **安全对齐**（safety alignment）：面向终端消费者产品（ChatGPT/Claude）的合理限制
- **能力对齐**（capability alignment）：追求绝对服从并准确执行用户指令——这才是底层 API 应该做的

他认为当前行业把安全对齐强加在底层 API 上，是"站在开发者对立面"。

### 3. RLHF 存在根本性缺陷：模式丢弃（Mode Dropping）

Diogo 支持 Yann LeCun 的观点：自回归 LLM 的训练方式存在根本问题。

> "为了生成足够长的文本且不出现明显错误，模型必须变得极度保守。这种所谓的'对齐'手段，对文本背后的概率分布具有破坏性影响。强行将文本生成模型直接应用于底层决策系统，本身就是一个根本性的错误。"

RLHF 训练出的模型倾向于输出"最迎合用户或概率上最平庸的内容"，而非对事实的真实置信度。

### 4. 公开基准测试是虚假信任

> "公开榜单太容易被刷分了，即使开发者主观上没有作弊意图，模型在训练时也会被动地产生过拟合。当年在 OpenAI 时，各大模型实验室都会专门组建团队，清洗并抓取与 MMLU 结构类似的数据来训练模型，纯粹为了提升榜单分数——这本质上是一种变相的'刷榜套利'。"

Jev 不做公开 benchmark，靠实际生产环境表现说话。

### 5. "放慢前沿演进"背后是政治算计

> "那些大实验室天天宣扬 AI 毁灭论、呼吁放慢研发节奏，背后根本不是什么人类生存危机。他们试图在推理环节绑架公众认知，很大程度上只是冲着 2028 年美国大选做的监管套利与政治站位。"

### 6. System Message 是"恶臭的全局变量"

> "把所有上下文和规则不管三七二十一全塞进一个大 Prompt，然后求神拜佛希望模型一次性全执行到位，这纯粹是被驯化的恶习。正确的工程做法是拆成上百个微小判定，让每个决策都可度量、可 Debug。"

## Jev 的技术定位

| 维度 | 传统 LLM | Jev（System 1 模型） |
|------|----------|---------------------|
| 消费者 | 人类 | 代码 |
| 输出 | 自然语言 | 带概率/置信度的决策 |
| 训练范式 | RLHF → RLVR | **RLCD**（Programs in the loop） |
| 安全性 | 内置拒答机制 | 零拒答，能力对齐 |
| 核心指标 | 智能 + 对齐 | **单位成本智能**（intelligence per dollar） |
| 速度/效率 | 慢 | 比同等智能 LLM 快两个数量级 |

## LLM 发展史上的三次范式转移

| 阶段 | 范式 | 核心转变 |
|------|------|----------|
| 第一次 | **RLHF** | 从预训练自动续写 → 指令遵循 |
| 第二次 | **RLVR** | 基于可验证奖励的微调 |
| 第三次（现在） | **RLCD** | 程序在闭环中调用 AI（programs in the loop） |

## 关于 Scaling Law 和数据

Diogo 认为 Scaling Law 揭示了资源投入与性能提升的关系，但边际收益往往是亚线性的。真正的关键是：**数据质量决定模型能力上限**。

> "Sutton 的核心论点在于：算力的提升终将胜过算法层面的优化。但在算力之上，数据显然起着比算力更为关键的作用。"

他将 TypeSafe 定义为"数据实验室"而非"模型实验室"。
