## 概述

文章称，升级后的 Grok Bot 支持用 Cursor 账号登录 PC 端应用，后台集成了 Opus 5.5、Midjourney、Suno 等模型，按任务自动路由调用。它还原生接入 X 数据，免 API 费用就能搜索、阅读、监控推文，并能接入微信。

## 关键内容

### 动态模型路由
- 用户只提需求，后台自动挑选模型：复杂代码架构或长文本逻辑走 **Opus 5.5**，设计走 **Midjourney**，配乐走 **Suno**；暂不能调用 GPT-Image-2.5，可用 Grok 自带的图像生成。
- 文中给出的 Opus 5.5 定价是 $4 / MTok 输入、$20 / MTok 输出，费用由平台补贴。业内人士判断这是前期的「闪电战」策略，用户涌入后后端模型清单可能收紧。

### Bot + Cloud Agents
- Grok Bot 团队成员 Lauren 确认，Bot 本身运行在 Opus 5.5 上，正在分批上线。
- 主 Bot 负责统筹，可生成 **Cloud Agents**（子代理），子代理能调用 Cursor 支持的任意模型。
- SpaceXAI 产品负责人 akshaya 的例子：客户通话中随口提了一个需求，Bot 几秒内写好产品需求文档，Cloud Agent 随即构建功能，最后 PR 待合并。
- 用户案例：
  - **Pulse**：每小时读取自己的 X mentions，过滤垃圾留言，只整理出问题、反馈、Bug、PR 和功能请求推送给自己。
  - **24/7 量化研究团队**：总控、市场情报、策略研究、验证、风控、组合建议、执行等角色分工；Opus 5.5 负责推理和代码，Cursor Agents 负责构建和回测。

### X 原生集成 + Routines
- 无需申请、无需付 API 费，智能体就能搜索、阅读、监控 X。
- **Routines**：后台定时任务 24 小时静默运行，结果直接推送。
- 文中列出的 7 种商业用法：行业晨报自动化、截流竞品用户、转化自有公域流量、捕获强购买信号、品牌口碑监控、销售拜访前背调、爆款内容拆解。

### 云电脑
- Grok Bot 背后有一台常驻的独立云电脑。和本地运行的 Cursor、Claude Code 不同，用户关机后它仍在工作。

### 接入微信
- 网友 Kin 的方案分三步，约 5 分钟：在电脑端 Grok Bot 里让它接入微信 → 配置一把专属「钥匙」 → 扫码绑定。
- 微信消息会转发给 Grok Bot 执行。作者实测让它生成了一段 30 秒的自我介绍广告视频，并用「Tibo 测试」（不联网也知道 Tibo 是谁）确认确实路由到了最新模型。
