## 概述

Kiki 平台同时运行 1000+ 个 Agent，作者要解决的是：多节点并行自我进化（RSI，递归自我改进）时，怎样从代码层面查清「谁改了什么」，又怎样在节点跑偏时马上叫停。

他的方案是借用比特币的 **UTXO（未花费交易输出）账本**：每项工作封装成一张「用完即作废」的 **ticket（一次性任务单）**，用确定性的代码规则代替提示词约束。

## 一、传统多 Agent 架构为什么扛不住大规模 RSI

**1. 共享状态表在千级并发下失控**
- 主流框架类似银行/以太坊的「账户模型」：一张全局共享状态表，所有 Agent 读写，由 Planner 决定下一步轮到谁。
- 四五个 Agent 还能运转；上千个并行改代码、跑实验时，会出现两类失控：Agent 无视冻结指令越权删改数据；两个节点互相退回任务，陷入无限循环。
- 作者评估过以太坊智能合约：写法灵活，但本质仍是「共享可变状态」。要在账户模型上补齐防重用、全链路溯源和无锁并发，等于重做底层。

**2. 没有可追溯账本，就不敢放手让它自我进化**
- 自我进化是一个闭环：发现问题 → 改代码 → 验证 → 带着经验进入下一轮。
- 卡住闭环的是人类的信任门槛：没人敢让一个能改写自身规则的系统跑一整晚，除非第二天能查清它改过哪里。
- 同构性：加密货币是互不认识的节点并发转账，这里是上千个 AI 并行改代码。两边的约束相同：没有中心权威兜底、节点会出错越界、必须记清每次变更的输入/归属/流向，并防住重复执行和死循环。

## 二、照搬比特币：一次性任务单

**1. UTXO 的三个工程特性**

UTXO 账本没有「余额」字段，只记录一组被签名锁定的离散输出。每次流转三步：指明要花掉哪几笔旧输出 → 签名验证持有权 → 生成交给下一任的新输出。旧输出花掉一次就永久作废。由此得到：

| 特性 | 含义 |
|---|---|
| 天然防重用 | 每笔输出只能消耗一次，第二个指向它的操作在校验层直接失效，不用查历史总账 |
| 自带全链路血缘 | 新输出严格连着上游输入，可一路追溯到源头 |
| 原生无锁并发 | 消耗不同输出的任务互不冲突，可任意顺序并行校验，不用锁整本账 |

Kiki 的任务调度层把每个任务单元做成 ticket，与 UTXO 一一对应。

**2. 四条代码硬规则，取代「模型自觉」**

1. **指令与数据隔离**：只有第一个输入槽位是指令；其他上游结果、网页内容一律放进「参考资料槽位」。网页里的提示词注入也只是数据，不会被执行。
2. **只有派单链条有权改单或叫停**：叫停 = 把根任务单花进 `end` 销毁地址。代码沿派单链往上核验权限，下游无权撤销上级派的活；根单进 `end` 后，派生的子单全部失效。手里没有有效任务单的 Agent，代码门禁不放行它碰数据库或生产环境。
3. **每次交接必须点名收件人**：没有「扔进公共池谁看到谁捡」，只能转给指定 Agent、退回用户，或送进 `end`。
4. **完结靠查账，死循环靠计数器截断**：请求是否结束，查根单下有没有未花掉的子单即可，不靠模型自己打勾；两个节点互相退单累计到阈值（如第 20 张）就熔断，交给人类裁决。

**3. 账本 + Git 双重留痕**
- Agent 修改规则或代码的每一步都是一张已消耗的任务单，记录上游单号、发起方和产出。
- 每交回一张任务单，系统自动把改动文件提交到后台 Git，Commit 信息强制附上任务单 ID。
- 分工：账本记「谁下令、为哪个问题改」，Git 记「具体改了哪几行」。
- 动作都是可计数的离散任务单，给自我迭代加上限几乎零成本。模型话术再能绕过提示词，也骗不过整数计数器。

## 三、离真正的 RSI 还差什么

**1. 从其他公链借鉴的四项机制**：原文以对照图列出，部分仍在落地中（图片内容未抓到）。

**2. 五阶演进路线**（Kiki 本周才刚搭好最底层的任务单账本）

1. **系统自主开单**：读到新论文、遇到高频报错、发现用户卡点时自动开根任务单；人类从逐一派活变成审批放行。
2. **规则赛马淘汰**：Agent 的行为规则是纯文本，允许它自己改写，但新版不能直接上线，要和旧版同跑一批历史任务，高分者留下，失败版本和原因记入账本。
3. **账本沉淀动态信用**：新 Agent 事事要问人，履历干净才逐步放权；犯一次严重错误，权限清零。
4. **验收者也接受复审**：打分和评审的 Agent 也在账本留痕，它的判断准不准，下一轮继续复核。作者认为到这一层才算真正「递归」。
5. **预算交易与外部结算**：任务单内嵌算力预算，Agent 用合格产物换算力；将来 Agent 有独立私钥后，内部账本可接通外部比特币结算网络。

## 要点与点评

- 核心思路：**用不可变、只能消费一次的离散任务单，取代共享可变状态**；用确定性代码规则（槽位隔离、派单链权限、点名交接、计数熔断）取代提示词约束。
- 每次改动都能计数、能叫停、能回溯，这是敢让系统无人值守自我进化的前提。
- 现状很早期：目前跑通的只是任务单账本 + Git 联动留痕；赛马、信用、复审、预算结算都还是设想。
- 不依赖区块链本身，借的是 UTXO 的数据结构思想；规则 1 和 4 可以直接用在一般的多 Agent 系统里（防提示词注入、防互相踢皮球）。
- 可与 [Anthropic：把 subagent 并回主 Agent 循环](2026-10-28-anthropic-fold-subagents-into-main-loop.md) 对照：那篇主张少拆 Agent，这篇解决的是 Agent 必须多到上千时怎么管。
