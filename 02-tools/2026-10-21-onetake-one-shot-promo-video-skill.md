## 概述

onetake 是一个 Agent 技能包（根目录带 SKILL.md），用代码做产品片、预告片和功能演示：不用剪辑软件，不录屏，没有一个镜头是摄像机拍的。它的核心理念是把**画面之间的交接处**当成最重要的设计对象：前一个画面里必须有一个东西活下来，并且看得见地变成下一个画面。这样做是为了避免「标题卡→淡出→界面→淡出→Logo」那种像翻 PPT 的观感。实现方式是 HTML + 一份动作库 + Playwright 渲染，不依赖 HyperFrames 或 Remotion。

## 关键内容

### 一、承接，而不是换场景

- 普通工具的思路是「排场景」，onetake 的思路是「写承接」。官方例子：
  - 输入框展开成 App 窗口，再重排成手机界面
  - 提示词输入框压成一条线，这条线变成下一条片子的第一根网格线
  - 卡片长成整个页面，镜头穿过卡片进入下一个场景
  - 结尾所有元素收拢，光标一笔写出名字
- 镜头从不剪断：提前半拍跟着主体走，像手持一样轻微浮动，东西撞上来时跟着一震，该停时完全静止。「因为有停顿，动作才落得下来」

### 二、连贯是量出来的

- `probe.py`：逐帧记录画面内容，找出所有交接处，判断有没有东西从一头带到另一头，算出**连贯度（carry score）**
- 同一条片子迭代三版：v1 节奏完美但像 PPT，carry 0.00，被否 → v2 0.40，被否 → v3 每个画面从上一个里长出来，0.75，通过；onetake 自己的发布片 0.83
- `verify_promo.py` 验收器判以下几类不合格：

| 判什么 | 不合格的样子 |
|---|---|
| 节奏 | 镜头长度全都一样（像按节拍器剪） |
| 静止 | 全片一直在动（参考片约三分之一时间是静止的） |
| 音质 | 爆音、削波、从头到尾没有一刻安静 |
| 曲线 | 快动作没有运动模糊，一格一格地闪 |
| 构图 | 主体跑出画面 |
| 连贯 | 画面互相替换（carry < 0.5），这是唯一同时判掉两个被否版本的标准 |

### 三、作者实测：60 秒中文旁白短片《一粒像素》

- 概念：一个镜头跟着一粒光点从像素退到银幕。光点四次换身份：方形像素 → 块状光标 → 光点 → 字标里 o 的圆心
- 六拍：
  1. 黑场中一粒 8×8 光点呼吸（0–6.4s）
  2. 长成光标，逐字打出提示词（6.4–17.7s）
  3. 镜头退出，露出五张卡，各演一个动作原语（18.6–31.4s）
  4. 卡片放大成画框，里面演成品《灯》（31.4–42.6s）
  5. 画框炸成 11 块银幕墙，片名硬切，是全片唯一的爆发段（42.6–50.4s）
  6. 一切收成光点，落进 o 的圆心，描出字标（50.4–60s）
- 验收输出：
  - 连贯度 1.00（3 个交接处都有承接）
  - 镜头长度 0.28–2.4 秒，相差 8.6 倍（要求 ≥ 4 倍）
  - 两段死静：一处 2.4 秒画音全停，片尾 2 秒
  - 45 段动作，71% 的位移走在软曲线上
  - 响度 −16 LUFS，峰值 −3.9 dBFS，18.4% 的帧是安静的
- 旁白只占 30.2 秒，其余 29.8 秒留给画面。规矩是不许拉长台词填时长，片长跟着旁白走

### 四、为什么看起来像成品

- **复刻界面**：按截图用 HTML 重建产品界面，推多近都清楚；不录屏，所以没有账号、水印或真实数据泄露
- **动作库**：约 39 个实测动作（弹簧、入场、衔接、碰撞、物理、镜头、流体光场），每个都是时间的纯函数
- **真实运动模糊**：快门张开期间多次采样，在线性光下平均
- **声音**：音效按片中事件摆放，共用一个混响空间，打点时音乐自动让位
- **结果确定**：整片是时间的纯函数，跳到任意时间点都得到同一帧，这也是运动模糊能实现的前提。草稿 1080p30，成片 4K60

### 五、安装与工作流

```bash
# Claude Code
git clone https://github.com/feitangyuan/onetake.git ~/.claude/skills/onetake
# Codex 等读取 ~/.agents/skills 的 Agent
git clone https://github.com/feitangyuan/onetake.git ~/.agents/skills/onetake
```

装好后直接用大白话提需求，例如「给我的 App 做个 15 秒发布视频」「按这几张截图复刻界面做功能演示」「我的动效视频像 PPT，帮我改」。

固定八步流程，违反硬规则直接返工：

1. 拆参考片：把静止占比、剪点、缓动方式量化成数字；不拆就做必被否
2. 出三个中心想法不同的概念，由人挑选，不许套模板
3. 写节拍表：镜头长短相差 ≥ 4 倍，写明每个交接处是什么东西活下来
4. 取素材：用真页面驱动录制，或按截图复刻界面
5. 合成一个 HTML 文件，所有值都是时间的函数，动作全部调库
6. 渲染：先出 1080p30 草稿（带运动模糊），验收通过后才出 4K60
7. 配声音：五样合成材质 + 统一混响；事件数要少于节拍数
8. 跑 verify_promo.py 验收，通过后再给人看

依赖：
- 必需：python3（playwright + chromium、numpy、scipy、Pillow、matplotlib）、ffmpeg、node
- 拆参考片：加 opencv-python
- 配音：faster-whisper + Kokoro

### 六、坑

1. **慢**：60 秒草稿就有 1800 帧，每帧多次快门采样，一跑十几分钟；不适合一句话出片
2. **不做长视频、口播、剪辑现有素材**：主场是 10–30 秒，带旁白的功能演示最长 60 秒；它连时间线都没有
3. **配音只有英语和日语**（Kokoro），中文要自己接 TTS
4. **不能商用**：PolyForm Noncommercial，商用需买 onetake Pro
5. **参考片那步不能跳**：不拆参考片，两次都被判成「像节拍器」；节奏达标但画面只是互相替换，照样被否

### 七、适用场景

- ✅ App / 产品发布片、预告片、功能演示（不录屏、多语言）、技术演讲开场片、救「像 PPT」的动效视频、10–30 秒社交短片
- ❌ 长视频、访谈、口播、剪现有素材、一键出片
- 判断标准：能说清「第一个画面里的什么东西要变成第二个画面」，就值得用
