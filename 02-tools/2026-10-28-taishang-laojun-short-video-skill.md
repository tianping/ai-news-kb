## 一句话

这是一套给 AI 智能体装的短视频创作技能，帮「不知道拍啥、不会写稿」的人做内容。它先弄清你是谁、想吸引谁，再把别人的爆款和你自己的经历「炼」成一条能直接念的口播稿。方法来自作者对自己作品的口述复盘，传的是判断方式，不是句式模板。

## 安装

```bash
npx -y skills add liuhaisi2026212-maker/taishang-laojun -g --all
```

- 支持 Claude Code、Codex、Cursor 等能装 skill 的智能体，也可以按 Claude Code 插件方式安装（仓库带 `.claude-plugin/`）
- 豆包、WorkBuddy 这类聊天智能体用 `bot-prompt/` 下的 **Bot 完整版**（约 1600 行）。设定框装不下时，用**精简版**（约 1000 行）当设定，完整版当知识库附件
- 装好后对 AI 说「用炼丹炉，我想拍视频但不知道拍什么」即可

## 结构：一个总控台 + 七件兵器（共 8 个 skill）

| skill | 名称 | 做什么 |
|---|---|---|
| `taishang-laojun` | 总控台 | 读懂用户此刻在哪、这次要交出什么，倒推调哪个模块；**没有固定流程** |
| `tslj-select` | 选材 | 找对标、拆爆款；用复读、客户、替换三关判断这个机制到你手里还成不成立 |
| `tslj-idea` | 看火 | 选题判断：从经历、场景、热点里给少量带理由的方向并推荐一个 |
| `tslj-series` | 丹方 | 系列策划：每期固定什么、换什么，首批五期，拍几期看什么信号决定继续还是换 |
| `tslj-open` | 开炉 | 开头与结构：第一句、紧跟的证据画面、中段、收尾；拍完后定剪辑顺序 |
| `tslj-script` | 回炉 | 完整逐字稿和改稿（包括改 AI 初稿） |
| `tslj-title` | 收丹 | 标题：先提炼「总」，再从「认人、认事、认心」三个角度出标题 |
| `tslj-monetize` | 成丹 | 变现承接：分清曝光、需求和成交，设计能兑现、合规的承接方式；不保证收益 |

## 设计理念：AI 当判断者，用户当校准者

作者用遍各家 AI 后最不满的三点是：方案落不了地、选题换谁都能用、把诊断推回给用户。所以规则反着来：

1. **先下判断，再问问题**：只问会改变结论的那一个问题，不问「你的目标受众是谁」这类问卷题
2. **每次落到一件今天能做的事**：拍哪条、第一句说什么、画面接什么。信息基本够时先给一版示范稿
3. **反泛货自检**：把建议原样给另一个人还成立吗？成立就重做
4. **对用户说人话**：内部框架名词不丢给用户，也不提「柳爷」「炉子」这些内部名字
5. **推断要标明是推断，但照样拍板**；**不编经历**：不知道这个人是谁，就不写第一人称经历
6. 用户自己总结不出来很正常，由 AI 从聊天里提炼出来，再交给用户确认

**炉心七条底层判断**：破冰先于一切（陌生人只给一两秒）；先替观众想出他心里的话（贪、懒、没意识到的痛点、对你的防备）；用事件衬托内核；判断力胜过教程（热点是载体，判断是内容）；钩子要马上兑现；展示什么就吸引什么人（成品招要成品的人，过程招学习者）；适合自己的才是兵器。

## 示例（README 里的测试实录）

AI 初稿写的是「在这个快节奏的时代……凝聚着大自然的馈赠……满满的乡愁与匠心」。改完以后变成：蹲在鸡窝边拿着刚捡的蛋，第一句直接说出观众心里的怀疑「网上卖土鸡蛋的那么多，你肯定在想，哪来那么多真土鸡」，下一秒用捡蛋的画面接住。「营养丰富」没测过，删掉；「还热乎」只在刚捡出来时拍才成立。

## 亮点：「去 AI 味」规则和检测脚本

- 两个核心检验：**念出来**（这话他跟朋友面对面会这么说吗）；**盖住原稿重新说一遍**（用五个问题重构：刚发生了什么、为什么现在开口、在跟谁说、手里能给人看什么、下一句是被观众哪个问题逼出来的）
- **第一优先是「假对比」**：不是 X 而是 Y、你以为 X 其实 Y、不只是 X 更是 Y，以及换了动词的变体，如「这不叫努力，这叫瞎练」「不难，难的是天天做」。**默认一句都不用，给用户的解释里也不用**
- `scripts/ai_tell_linter.py`：用正则预检假对比（硬拦截）和空转词（软提醒），支持允许清单和 JSON 输出。仓库的 CI（`check_package.py`）也用它扫自己的技能文字，命中即失败。空转词清单参考 Humanizer-zh（MIT）

## 工程做法值得借鉴

- `docs/validation.md` 记录每个版本**改了什么、怎么测的、哪些补丁之后还没再测**。测法是：虚构用户场景，新旧版本各答一遍，再匿名评审（例如 0.7.0 新版赢 3 输 1 平 1，总分 109 比 99）。作者坦白「只有模拟用户，没有真人试用」
- 0.7.1 处理过一次反馈：有人在 WorkBuddy 不给个人信息直接要稿，出来约 6000 字的模板化图文，朱雀检测 100% AI。作者复现了 24 篇都没复现，判断问题出在宿主没按规则执行，同时补了「不编第一人称经历」等规则
- 0.7.2 承认「AI 很难在网上找准抖音对标，搜不到就容易编」，改成 AI 定方向和标准、用户自己在抖音搜、搜回来 AI 筛
- 单一版本源（`plugin.json`），由 `build_views.py` 自动同步人读版、两份 Bot 和全景图

## 个人评价

- **适用**：想做短视频或口播的个人、小店主、替老板做号的人；也可以当「如何写一个高质量中文 skill」的范本看，比如判断优先、反泛货自检、写在 CI 里的去 AI 味检查、诚实的验证记录
- **局限**：效果依赖宿主模型是否老实执行长规则（WorkBuddy 那次就是反例）；方法来自作者个人复盘，作者也说明「口述效果不等于逐条因果验证」；非商用许可，商业使用要另找作者授权
- 结构设计参考了 dontbesilent/dbskill
