## 概述

Claude Code v2.1.302 于北京时间 2026-10-17 04:53 发布，更新日志共 63 条。文章挑出两个以前用户无法调整的开关：自动模式的客户端分类器可以通过环境变量换模型；空闲压缩（Idle compaction）可以在 `/config` 里关闭。两者都关系到等待时间和 token 费用。

## 关键内容

### 开关一：`CLAUDE_CODE_AUTO_MODE_MODEL`
- 自动模式下，每次工具调用先由分类器判断是否安全，安全就直接执行，拿不准才询问用户。以前分类器模型由系统指定，慢且偏保守
- 新环境变量设成模型名即可替换：想快换小模型，误判多换更强的模型
- 三个限定：
  1. **只影响客户端判定**，服务端还有一套分类器不受此变量控制
  2. `claude -p` 和 Agent SDK 在第三方供应商、关闭遥测或全新安装时，无权限设置的会话**默认改为 default 模式**，不再默认自动；要继续自动需显式加 `--permission-mode auto`。批处理脚本升级后行为变化多半因此
  3. OpenTelemetry 的 `tool_decision` 事件补上了 `classifier_category` 字段（以前看不到被拦原因），并修复新属性挤掉 `tool_use_id`、`tool_source`、`tool_parameters` 的问题
- 配套改进：服务端分类器遇到对话过长时，以前直接拒绝所有工具调用，现在先压缩对话再继续检查

### 开关二：Idle compaction（空闲压缩）
- 用户不输入的空当，Claude Code 会自动把旧对话压成摘要腾出上下文。以前只能自动，现在 `/config` 里可以关闭或重新打开；压缩完成的提示条会直接说明怎么关
- **谁该关**：做长任务的人。摘要是二手转述，文件路径、完整报错堆栈、早先随口给的约束等细节容易丢
- **代价**：关掉后上下文涨得快、token 烧得多，是"拿钱换确定性"；以聊天为主的用法建议保持开启
- 同版修复的压缩相关问题：
  - 压缩进行中按停止不再报「Prompt is too long」
  - 网关给模型名加前缀（如 `anthropic/claude-opus-4-1`）时，`/autocompact` 和 `/effort` 会把设置存到错的模型上
  - 会话中途新增的工具经 ToolSearch 重新加载或经历一次压缩后会打穿提示词缓存，已修复
- **缓存账**：提示词缓存命中部分通常约按一折计价，命中要求请求前缀与上一轮一字不差。压缩会改写前半段对话，每压一次缓存断一次；工具定义变化同理。本版修了"中途加工具导致缓存 miss"，但压缩造成的断点仍在

### 其他值得知道的变更
- **Read 工具**：超过 128 MB 的图片源直接拒收（以前会整个读进内存，包括长得像图片的管道/设备文件）
- **插件**：市场刷新不再每次重新 clone（git 新版默认 reftable 引用格式踩坑），新装 git 插件版本号不再显示 unknown；多插件启动减少文件系统调用，Windows 改善最明显；`claude plugin` 子命令不再在配置写入完成前退出（以前可能丢改动并留 `.tmp` 文件）
- **Windows**：项目放在 exFAT/FAT32 盘（移动硬盘、双系统分区）上时，每次写入被拒或弹确认的问题已修复，含 `--plugin-dir` 会话
- **Claude Design 关停通知**：`/design-sync`、`/design-login` 会提示独立的 Claude Design（claude.ai/design）将于 **2026-12-14** 关停
- **子代理**：桌面端和 VS Code 主对话的子代理总在后台运行（与终端一致）；子代理自己发起的 Agent 调用在 `claude -p`、SDK、桌面端、VS Code 默认回到前台；fork 子代理在这些环境默认开启，`CLAUDE_CODE_FORK_SUBAGENT=0` 可关闭
- **Hooks**：同一事件最多 12 个并发，超出排队
- **MCP**：兼容协商 2026-07-28 版协议时省略 `resultType`、`ttlMs` 或 `cacheScope` 字段的第三方服务器（以前表现为工具全不显示或调用全失败）
- **云会话**：新进程恢复后成本/用量统计不再从零重算；定时例程中途失败后一小时从头重跑导致报告重复发送的问题已修；例程页面会显示上次未运行的原因（如组织并发会话数到顶）；「Rewind to here」可回退到中间任意消息（自托管 runner 需 v2.1.246+）
- **提示词建议**：积分计费的回复之后不再生成提示词建议，避免消耗积分

### 升级后检查清单
1. 升级到 v2.1.302，在 `/config` 里决定 Idle compaction 开还是关（长任务为主 vs 聊天为主）
2. 用自动模式的试 `CLAUDE_CODE_AUTO_MODE_MODEL`；检查 `claude -p` 脚本，第三方供应商上需显式加 `--permission-mode auto`
3. 插件多、工作区在 exFAT 盘、被「Prompt is too long」困扰过的用户都应升级

## 影响 / 备注

- 两个开关的共同点：以前由系统决定的事（判定用什么模型、何时压缩对话）交还给用户
- 与本机相关：OpenClaw 通过 `claude -p` 调用 Claude Code 时，若走第三方供应商，升级后权限模式默认值可能变化，需留意
