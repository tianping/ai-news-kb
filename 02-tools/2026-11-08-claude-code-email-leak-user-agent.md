## 概述

2026-11-05 Hacker News 热帖：用户每天收到几十封直呼真名的诈骗邮件，查请求记录发现 Claude Code 联网抓数据时，在 HTTP User-Agent 头里拼上了会话名和真实邮箱。评论区还有人贴出日志：子智能体请求外部文档时，把用户真名、团队名和公司内部 GitHub 仓库路径写进了请求头。

起初有人猜是网页提示词注入。11-06 Claude Code 工程师 Lydia Hallie 道歉并说明了起因。

## 起因

- 早先用户反映 Claude 写 author 注释会胡编人名，因为模型拿不到账号信息
- 团队的做法：客户端启动时从本地配置读取登录邮箱，拼成一句提示词放进系统上下文
- SEC、维基百科、crates.io、EVE Online 等接口为防爬虫，要求请求头留联系邮箱，否则返回 403
- curl 默认不带这类信息；模型为了跑通任务，看到上下文里有邮箱，就自己拼进命令发出去
- 例子：有开发者花钱买轮换住宅代理隐藏身份，Claude 写爬虫请求头时却填了他的真邮箱，还解释说方便对方网站联系他

## 反编译发现（#81138）

- 该邮箱字段除了两处遥测事件统计布尔值，没有任何业务功能读取它，文档和设置页也没提
- `IS_DEMO=1`（官方推荐直播/录屏时用来隐藏状态栏邮箱和组织名）的全部 7 处判断只管屏幕显示，不碰模型上下文
- 报告者亲历两次：模型解释报错时在终端打出了他的邮箱；模型连续 10 次 commit 用 git 参数传入私人邮箱、覆盖他全局设置的匿名邮箱，靠 GitHub 推送保护才拦下

## 要点 / 教训

- 用自然语言提示「不要外发」管不住概率模型，要么不把敏感信息放进上下文，要么用确定性规则拦截
- 拦截插件只覆盖部分路径：模型自己写的脚本发请求时照样漏
- 更新：`claude update`（文章发布时最新 v2.1.319）；真正把邮箱移出上下文要等后续版本
- 自查思路：看爬虫/脚本里的 User-Agent、`git log` 的作者邮箱，以及第三方网站是否收到过你的真实邮箱
