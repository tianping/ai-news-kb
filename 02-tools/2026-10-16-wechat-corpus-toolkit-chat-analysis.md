## 概述

开源的微信语料**本地分析**工具链。「拿到聊天记录」这一段直接继承 tzwkb/wechat-decrypt（全量 git 历史，作者 cocofeng）；本项目补的是之后的**分析**：导出组织、分析库、建图、27 个分析工具、报告生成、智能体操作手册。用途：识别社群 KOL、还原观点演化、查证自述真伪，产出每条断言可溯源到原消息的报告。设计为「把仓库地址丢给 AI 智能体，关键节点找你确认，其余自动」。环境 Windows 10/11，全程本机。

## 解决的五个问题

1. **以「上下文回合」为分析单位**：发言流切成「发言块 / 回合 / 窗口」三层，单条消息脱离上下文没有意义（「牛」是赞叹还是敷衍看前一条）
2. **观点一致性与演进**：观点当轨迹不当快照，跨时间、跨群核对；表面矛盾回原文裁定
3. **KOL 识别与画像**：从交互结构而非发言量识别关键人物；三层标签——说话节奏类型、观点签名、群体角色
4. **KOL 间关系**：从高频交互对提取求教/情绪支持/商务/对抗等关系类型及演化；「称呼温度计」——称呼突然切换常是关系变化的硬信号
5. **自述验真**：自报履历、资源、公司产品与公开信息核对，三态标注：已验证 / 待验证 / 已证伪；未验真信息强制标注，不混入结论

架构判断：**代码做结构，LLM 做判断，两层硬分界**。

## 全流程（获取 → 导出 → 分析）

1. **获取**：按基座项目流程提取全量聊天记录（机制、适用版本以基座文档为准）；高权限节点先向用户确认
2. **导出**：建群聊/私聊候选池，看活跃度后**勾选**要导出的会话；时间窗可选最近 N 天或区间，支持增量续导；新扫到的会话默认不导出
3. **分析**：
   - 归并进分析库，六张表：消息、联系人、群、关系边、别名、指纹
   - 建图前置（必跑）：引用关系、同现、同人不同称呼归并、每人说话指纹
   - 27 个分析工具按需调用：群画像、人物证据卡、关系往返对、观点演化、金句提取、私聊画像、全库总览等
   - Markdown 报告渲染成 HTML

## 方法论：「代码备料，LLM 掌勺」

- 有精确答案的交给代码：整理数据、归并称呼、统计互动、提取说话特征
- 需要理解含义的交给大模型：判断褒贬、可信度、把证据写成报告
- 词频、聚类只许用来缩小范围、辅助抽样、发现异常，**不许直接贴标签下结论**（「强」字出现 120 次 ≠ 吹捧 120 次）
- 四个理论支柱：
  - **Goffman 自我呈现**：多群即多个前台 → 分析次序先群、再跨群、后个人
  - **对话分析**：回合是社交行为的真实单位；回合数 = 参与次数，中位跨度 = 卷入深度，每回合块数 = 节奏（连发型 / 快闪型 / 深水型）
  - **立场检测**：全量候选、指纹、演化、一致性三轴；正序看流，倒序看因
  - **证据科学**：未还原被引原文不得下结论；没进证据卡的断言不得进报告；降级任何断言前必须全库搜索

## 安全与隐私

- 产物是全部聊天记录的完整本地副本：开全盘加密；产物目录脱离云同步盘和共享目录；不用时清理
- **先审计再运行**：核心文件不到一千行，约一小时读完；全局搜网络请求应为零外发路径；git 历史可逐 commit 对回上游；只从官方地址 clone
- 隐私七原则：数据不出本机；库内保留全名、外发走 hash 脱敏；PII 花名册单点脱敏；本人账号归并到保留键不暴露 wxid；验真只查公开信息、永不人肉；工作群语料外发前必须脱敏

## 两种用法

1. **智能体全托管（推荐）**：把仓库地址交给 Claude Code / Codex / OpenClaw 等，智能体读 README 中的 Agent Guide 和两份带触发词的 SKILL 手册，按规则跑全流程
2. **人工打前站**：自己 clone 到纯英文路径、Python 3.10+ 建虚拟环境装依赖、完成获取与导出；再让智能体读 SKILL 手册接手建库、建图、分析与报告
