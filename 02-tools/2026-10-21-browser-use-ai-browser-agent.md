## 概述

Browser Use 是一个开源框架，让大模型自己操作浏览器：用一句话说清要办的事，它打开浏览器、看着页面决定点哪里，一步步做完。和传统自动化脚本的区别是**流程不写死**，每一步由模型判断。它同时保留写死的代码路径：确定的步骤用代码，不确定的交给模型，两者可在同一会话里混用。

作者指出宣传语里没说的两件事：
1. **每一步都要调一次模型**，任务越长越费钱
2. **数据上报默认开启**：官方文档写明会收集任务内容、访问过的地址和最终结果

## 能力

- **一句话开跑**：不用写步骤。官方示例是「查一下这个项目有多少星」
- **基本操作**：点击、输入、滚动、翻页、开新标签。查资料时另开页签，不覆盖当前页
- **自我核实**：每次操作后对比截图和元素表的变化，不默认操作成功；页面变了就重新规划
- **卡住换路**：同一地址连续三步没进展，或同一动作失败两三次，必须换办法并记下试过什么；遇到拒绝访问、反爬、限流，换站点或换搜索路径，不反复重试
- **验证码在云端处理**：本地库不解验证码，由云浏览器那一层监听代理消息处理。已知限制：同一时间只盯一个，几个同时出现时只盯最后一个
- **登录 = 借用已有登录态**：可以指定复用本机已登录的浏览器配置。给模型的规矩是「没必要就别登录，没账号密码就别登录」，不会自己注册账号或猜密码
- **文本提取**：专门的提取模块能把整页结构化信息抓成干净文本，包括页面上没显示的部分
- **省钱的动作**：页内搜文字、用选择器查元素（比如数表格几行）不经过模型，又免费又快；「抓取」动作被标为很贵，不要对同一页反复调用
- **Actor 接口**：官方称为「遗留的直接浏览器控制」，是基于浏览器调试协议（CDP）的底层自动化，用于精确操作。强调是自研的，不是 Playwright
- **编码助手技能包**：6 个，覆盖浏览器控制、云服务、开源库、质量评测、远程浏览器、支付，用 uv 一条命令装
- **17 家模型**：Anthropic、AWS、Azure、自家模型、Cerebras、DeepSeek、Google、Groq、LiteLLM、Mistral、Oracle 云、Ollama、OpenAI、OpenRouter、Vercel 等，另有兼容 OpenAI 协议的通用入口。国内用 DeepSeek 可直连，Ollama 可完全本地运行

## 使用步骤

1. 装库：官方推荐 uv，先 `uv init` 新项目，再加入 browser-use
2. 在 `.env` 里写模型密钥
3. 写一个最小脚本：

```python
import asyncio
from browser_use import Agent, ChatOpenAI
from dotenv import load_dotenv
load_dotenv()

async def main():
    llm = ChatOpenAI(model='gpt-5.6-luna', reasoning_effort='xhigh')
    agent = Agent(task="查一下 browser-use 这个项目有多少星", llm=llm)
    history = await agent.run()
    print(history.final_result())

if __name__ == "__main__":
    asyncio.run(main())
```

4. 运行：浏览器会自动打开，模型自己去找答案并打印出来
5. 换模型：用官方云模型就换成官方的模型类，完全本地就接 Ollama
6. 用自己的浏览器：指定本机已登录的配置，接着你的登录态干活；云浏览器用另一个参数
7. 加自己的工具：按它的方式注册一个 Python 函数，流程里就能调用
8. 装进编码助手：把官方提示词粘给 Claude Code 这类助手，让它去安装、注册技能、连上浏览器
9. 控制步数：运行时显示「第几步 / 共几步」，上限是参数，默认 500

## 真正解决的问题

1. **接管「不确定怎么走」的那段**：页面和预期不一样、按钮点了没反应、弹窗挡住内容时，它能自己换办法
2. **把网页翻译成模型能用的形式**：给可交互元素编号，模型不用读懂源码，只需说「点 38 号」
3. **长任务有记忆**：任务级备忘加一小块文件空间，几十个条目的活能分步推进，中途能查进度
4. **写死的操作和模型判断放在同一条链上**：确定部分用代码（不花钱、稳定），不确定部分交给模型（灵活），这是它区别于纯 AI 自动化和纯脚本自动化的地方

## 与同类对比

| 对比对象 | 区别 |
|---|---|
| 传统爬虫 | 爬虫是「请求→解析→取数」，本质是拿数据；它是「打开→看→操作」，本质是做事。它没有批量和并发设计，批量抓数据很贵 |
| Playwright 类框架 | 那些是确定性框架，靠选择器写死。它的底层接口是自研的：查元素立即返回、不等元素可见，跳转后要自己等 |
| 其他 AI 自动化方案 | 用编号表把页面压缩成模型可引用的编号，而不是塞源码；截图用来核实结果，不只是用来触发操作；开源部分可以完全跑在本机（自己的浏览器 + 本地模型） |

官方技能说明里有一节「什么时候别用」：抓公开信息不需要浏览器，普通请求能读到的就用命令行取。只有需要交互、需要用户登录态、需要执行页面脚本，或页面有反爬时，才轮到浏览器。

## 边界：成本和成功率

- 官方基准：最难的 60 道浏览器任务，每题成本从 5 美分到超过 10 美元不等
- 最高分是 GPT-6 Astra，77.3%；多数模型在 10%–40% 之间
- 官方补充：简单任务上，小模型也能拿到很高的成功率
- 结论：最难的场景里再好的模型也做不到全对；分数和成本绑定，往上走一档，价格翻几倍
