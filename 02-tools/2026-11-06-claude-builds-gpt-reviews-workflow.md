## 核心观点

- 国内用户偏爱 Claude 的两个原因：**快**，以及**猜心思猜得准**——这两点对入门用户吸引力尤其大
- 但快 ≠ 对。Opus 5.5 聪明到只需交代前因后果和期望就能自己找路径；做即兴项目（Karpathy 式 demo）很好，长期项目却容易「萝卜快了不洗泥」，一条路走到黑、把产品思路带偏——跨界新手往往不知道自己「住在危房里」
- GPT 的毛病是磨叽、思前想后、前后找补（写文章时要严令它别端水），但这个毛病**放在任务审核和 code review 上反而出奇地好**：Codex 审完代码，Opus 收到反馈常回「这是真 bug，得改」
- 结论：Claude 最大优点是快速试错、快速验证；要稳稳接住任务还得配一个 GPT 做评审

## 编排原则（作者的系统，原建在 Herdr 上，现迁到 Orca）

1. **少做协调工作**：协调 Agent 负责派单、跟进、收结果，人不用在窗口之间复制粘贴
2. **多一次独立检查**：开发与评审分开；评审者看完整代码和验收标准，自己找证据
3. **交接更容易**：共用任务书、标准和结论文件，各自保留独立上下文，换会话也能续上
4. **按任务选流程**：小改动直接派；需要检查时加评审；长程任务走完整流程
5. **问题跟到底**：评审不通过就返工，通过后再独立验收；重要决定仍由人拍板

作者建议：把这几条和流程图发给自己的 Claude，让它编排出对应的 skill。好处是流程不绑死在某个模型上——没有 Claude 时换 DeepSeek 也能跑。
