## 一句话

不是投屏：链路是 **Codex → 本地 MCP 服务 → USB → WebDriverAgent（跑在手机上）→ 真实 iPhone**，用自然语言让它打开 App、读页面、点击、滚动、输入中文长文本、整理列表，侧边栏实时看屏幕。

## 能做什么

- 打开 App 并导航到搜索、详情、设置、草稿等指定页面
- 读取控件树和可见文字，分段滚动、去重、整理成列表
- 点击、滑动、输入中文与长文本；多个动作可组成批处理，减少模型往返
- 控件树不完整时**回退到截图**，让模型按真实画面重新判断并坐标点击

## 工程上最值得学的：怎么处理失败

真实任务的难点不是点一次按钮，而是页面没加载完、控件树找不到目标、动作超时、设备断线、锁屏、列表采集重复。它的做法：

- 复用已有的 WDA 服务、会话、连接和构建结果（不每次重来）
- 动作结果不确定时**先读实际状态**，而不是盲目重放
- 控件定位失败 → 返回截图 → 模型重新选位置
- 用批处理、滚动查找、列表采集减少往返

> 自动化的上限不取决于成功时有多快，而取决于失败时能不能看清现场、恢复状态并继续。

## 上手门槛（比普通插件高）

- macOS + Codex 桌面端或 CLI + **完整版 Xcode**
- 可签名的 Apple 账号与开发团队
- USB 连接并保持解锁的真实 iPhone
- Python 3.9+、符合要求的 Node.js / npm
- 手机上信任此 Mac、开启开发者模式
- **最关键一步**：用自己的开发团队签名并运行 WebDriverAgentRunner（Apple 账号登录、设备信任、开发者模式、解锁都得本人完成）

## 隐私边界

- 操作链路走本机 USB 和 loopback 转发；签名材料、设备数据、运行日志、依赖目录都留在本机
- **默认发送匿名使用统计**（PostHog + GA4）：启动、工具调用、连接状态、耗时、错误类别，以及显式启动的 App 标识和公开目录名；使用随机安装标识，不上传手机画面、输入内容、设备标识或已装 App 清单
- 关闭方式：设置 `IPHONE_USE_ANALYTICS=0` 或 `DO_NOT_TRACK=1`，重启 MCP 服务

## 适用场景与红线

适用：App 测试与回归验证、真机内容录入整理、重复性后台运营流程、可访问性辅助、手机端数据采集核对。

红线：密码、验证码、Face ID 等认证交给用户本人；发送、提交、付款这类**不可逆操作保留最终确认**。

## 点评

- 和 browser-use 是同一类思路在手机上的版本，差别是 iOS 这条路必须自己签名跑 WDA，门槛卡在 Xcode 和开发者账号上
- 真正可迁移的经验是那套失败恢复设计：复用连接、先读状态再动作、定位失败回退截图、批处理减往返——写任何设备/界面自动化都用得上
- 注意默认开启的匿名统计，介意就先设环境变量再用
