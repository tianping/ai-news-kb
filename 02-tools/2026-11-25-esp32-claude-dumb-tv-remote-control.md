## 一句话

一台没有网络的老电视通过 HDMI 接台式机，Rust 程序员 Quentin Santos（ENS 密码学博士）用 ESP32-C3 + 红外收发模块读取电视遥控器的 RC-5 编码，经 Wi-Fi 通知电脑执行动作，让 Claude Opus 5.5 写大部分代码；最后四个彩色键分别是看剧、模拟器游戏、壁炉模式、Steam Big Picture。

## 硬件与原理

- 红外发射器 + 接收器、ESP32-C3 Mini、迷你面包板、杜邦线
- 电视遥控器按键发 RC-5 红外编码 → ESP32 识别是哪个键 → Wi-Fi 发给电脑 → 电脑执行脚本
- Claude 帮忙识别各按键的 RC-5 编码并写控制脚本
- 第一个目标：一键完成"打开第二块显示器 → 启动播放器 → 窗口移到电视 → 全屏"

## 四个彩色键

| 键 | 功能 |
|---|---|
| 1 | 影音播放 |
| 2 | 游戏模拟器：ES-DE 前端统一管理 DuckStation（PS1）、PCSX2（PS2）、Dolphin（GameCube/Wii）、Cemu（Wii U），两只 Xbox 手柄 |
| 3 | 壁炉模式：循环播放 10 小时壁炉视频 |
| 4 | Steam Big Picture（为电视和手柄设计的界面） |

## 窗口跑错屏 → Multiseat

- 双屏单桌面时，程序窗口常出现在错误的屏幕上
- 改成 **Multiseat**：显示器和电视各跑一个独立的 X 会话，相当于一台电脑两个桌面，工作与娱乐互不干扰
- 副作用：日常桌面没法直接操控电视那一侧 → 让 Claude 写**管理面板**：
  - 虚拟电视遥控器，可经 ESP32 发红外信号；ESP32 跟踪实体遥控器的音量变化，让虚拟面板保持同步
  - 远程向电脑发命令启动/切换应用
  - 虚拟游戏手柄
  - 电视画面实时串流，可点鼠标
- 自动化：打开一只 Xbox 手柄就切到模拟器/Steam 模式；最后一只手柄关闭就回到壁炉模式

## 耗时与对 Claude 的评价

- 全程约 10 小时，大部分花在模拟器安装配置和优化响应速度上（按键后要等就失去意义）
- Claude 写乐鑫微控制器代码比他自己快得多，但需要**严格监督**：会把方向带偏、留下明显 bug、提出看似合理却没解决根本问题的修复
- 他认为没有 AI，单是最初的遥控器功能就要花很多时间，后面也未必有动力扩展到模拟器和管理面板——AI 降低的是"算了，太麻烦"到"做出来"的门槛

## 点评

- 和库里 Codex 改 Android 电视那篇是一对：那篇靠 ADB 改智能电视系统，这篇是给"傻电视"外挂一套 PC + 红外桥接
- 可复用的思路：ESP32 + 红外模块做桥，任何带红外遥控器的旧设备都能接进自动化；Linux 上 Multiseat 解决"一台机器同时服务两块屏、两个人"
