## 一句话结论

iptv-org/iptv 不存任何视频，只收集全球"版权方主动公开"的 IPTV 直播流链接。13.6 万 Star 投的不是链接本身，而是把"全球有哪些公开频道"这件脏活整理成了基础设施——主播放列表 + EPG + 数据库 + API + 资源清单分工咬合。

## 它是什么

- **只收链接，不存视频**：仓库里没有任何视频文件，存的是指向公开直播流的 URL（README 法律声明写得很直白）
- **边界是"公开可用"**：收录的是版权方有意公开的流，不是私服、不是盗播聚合
- **元数据**：主语言 TypeScript，协议 Unlicense，默认分支 master；证据快照（2026-09-06）Star 数 136,614，快照前最近一次推送 2026-08-24
- **属于 iptv-org 组织**，不是一个孤立仓库

## 怎么用（粘贴—打开两个动作）

- **官方用法只有一步**：把主播放列表链接粘贴进任何支持直播的播放器，按下 Open
- **主列表**：`https://iptv-org.github.io/iptv/index.m3u`（包含仓库全部可用频道）
- **细分类**：其他播放列表链接在 `PLAYLISTS.md`
- **播放器清单**：README 把 "any video player" 指向 iptv-org/awesome-iptv 的应用清单
- **零部署**：不用克隆代码、不用装专用客户端

## 频道背后的一整片生态（分工咬合的机制）

| 仓库/资源 | 职责 |
|-----------|------|
| iptv-org/epg | EPG 电子节目单，下载工具可接进播放器查"现在播什么/接下来播什么" |
| iptv-org/database | 所有频道数据源；发现数据有误去这里开 issue，不在主仓库 |
| iptv-org/api | API 文档，把频道清单变成程序可调用数据 |
| iptv-org/awesome-iptv | 播放器与资源清单（"拿什么播"的答案库） |
| FAQ.md + discussions | 常见问题 + 公开讨论区（推荐先看 FAQ 再进讨论区） |

任何一个单独看平平无奇，串起来就是一条"频道有哪些→节目怎么播"的完整链路。

## 13.6 万 Star 凭什么

- **把"整理"做成基础设施**：解决的是"发现"问题——把散落全球的公开频道源收敛成一条可粘贴的主列表，再用 database + API 锻造成机器可读的基础设施
- **自动化在背后**：README 首行挂着 GitHub Actions update 工作流徽标，列表由自动化流水线持续更新，不是建完没人管的静态文件
- **法律边界写得像范本**：不存视频＝提供链接的站点没复制内容；版权方若认为某链接侵权，按 `6_copyright-claim.yml` issue 模板要求移除，下架入口对所有人公开
- **贡献与资金通道透明**：README 末尾展示 OpenCollective 支持者与贡献者名单，贡献规范写在 CONTRIBUTING.md
- **量级是真实用户投票**：在"频道源反复失效"的常态里，十几万人把它当成可依赖的入口

## 谁适合先收藏

- 用 VLC 等支持直播的播放器看公开频道的人（粘贴主列表就能开播）
- 想拓宽频道视野、看不同地区公共频道的人
- 需要 EPG 节目单、追节目不想靠撞运气的人
- 做 IPTV 相关开发、需要频道数据的人（database + api 是现成数据源和文档）
- 想参与开源的人（清晰的贡献指南、公开讨论区、支持通道）

## 边界（先讲清楚的几个"实在话"）

1. **链接的"保质期"不在仓库手里**：仓库对链接指向的目标没有控制力，链接失效/下架时删掉播放列表里的链接不会删除网上内容——给的是"随时在变的公开源索引"，不是"永久可用"承诺
2. **是"公开源索引"，不是"免费看付费内容"的入口**：项目方声明收录的是据其所知版权方有意公开的流；具体某频道能否看、怎么用才算合规，取决于内容来源与当地法律
3. **所有数字都有"快照日期"**：Star 数、推送时间来自 2026-09-06 快照；播放列表内容、频道数量、EPG 覆盖都在持续变化
4. **Star 数不等于可用性**：播放列表本质是"链接的集合"，不是"频道的保证"——当检索入口用，别当服务承诺

## 写在最后

一个不存任何视频文件的仓库凭什么攒下 13.6 万 Star？因为它解决的根本不是"存储"而是"发现"。开源世界里稀缺的往往不是炫酷的代码，而是有人愿意把"整理"这种脏活、细活长期做下去。覆盖全球公开频道的清单不直接赚钱，却要常年盯着更新、维护频道数据、处理版权申诉——平台没动力把它当主业，只有开源社区愿意把它当"公共品"来养。一个人维护是负担，一群人维护就成了基础设施。
