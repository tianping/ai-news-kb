# 一文看懂 Claude Opus 5.5 额度利用：多了 25%，够不够用看轮数

- **日期**：2026-10-07

## 概述

换到 Opus 5.5 后，Pro、Max、Team 订阅额度大约能多用 25%。额度花得快还是慢，主要看三件事：**来回转了几轮、缓存有没有断、想了多久**。网上流传的「便宜 40%」是按 API 计费估算的，订阅用户记 25% 就够了。

## 这次对订阅用户的变化

- 额度约多 25%：Opus 5.5 比 Opus 5 便宜，差价直接折进额度。
- 五小时额度上调，覆盖 Pro、Max、Team 和按席位计费的 Enterprise。
- 符合条件的用户有**一次额度重置**，时间自选。入口在网页版或桌面版的 Settings > Usage，终端里没有；重置对整个账号生效，包括 Claude Code。
- **默认 effort 从 high 降到 medium**。

## 额度花在哪：每轮都重发整段对话

Claude Code 做任务是一轮一轮转的：读对话、调工具、看结果，再来一轮。每一轮都要把前面整段对话重发一遍。缓存命中时，这次重发很便宜；缓存失效，就要整段重算，最费额度。

- **轮数越少越省**：多一轮，花掉的不只是新增内容，还有前文全部重发。
- **缓存别断**：订阅用户的缓存保持 **1 小时**，超过 1 小时再回来，下一轮整段重来。开始用 usage credits（超出套餐的额外用量）后，缓存寿命降到 **5 分钟**。
- **思考也算钱**：Opus 5.5 每次回答前都会思考，关不掉。即使你只看到摘要，完整思考过程也在消耗额度。
- **会让缓存重来的操作**，最好在会话开头定好、中途别动：换模型、连接或断开 MCP 服务器、第一次打开 fast mode、对话被压缩。

## 四个省额度的习惯

1. **effort 从 medium 起步，卡住再升**（`/effort medium|high|status`）
   - 同一档位下 Opus 5.5 比 Opus 5 想得更多，别照搬以前的 high。
   - 任务中途改档，订阅用户不丢缓存。
   - 升档前先想想能不能让模型自己验证结果，比如跑一遍覆盖调用方的测试。跑测试只多一轮，升档却是每一轮都多想。
2. **难题换 Fable 5.1，查资料交给小模型**
   - Opus 5.5 开 xhigh、同一问题**失败两次**，就换 Fable 5.1，别等第三次；解决了再换回来。注意 `/model` 会把选择记成以后新会话的默认值。
   - 找文件、读日志、看测试输出交给 Haiku 或 Sonnet：在子代理定义里写一行 `model: haiku`。
   - 改代码留给 Opus 5.5；批量机械修改把 effort 调到 low 就够。
3. **换话题用 /clear，要休息先 /compact**
   - `/clear`：清空对话，不耗额度，切到不相关的工作时用。
   - `/compact`：把旧对话压成摘要，本身要耗一次。**趁缓存还热、休息之前压**，可以写明要保留什么，如 `/compact 保留失败的测试名`。
   - `/rewind`：走错路时退回之前某一轮。
4. **开口之前加载的东西，每轮都在重发**
   - CLAUDE.md 每轮重发，官方建议控制在 **200 行以内**；只在特定流程用到的长说明挪进 skill，用时再加载。
   - 跑 `/mcp`，关掉用不到的服务器。
   - fast mode 更快，但按**双倍价格**走 usage credits，不占套餐额度；要开就在会话一开始开。

## 用 /usage 查额度去向

- 显示套餐用量条，并列出 skill、子代理、plugin、各 MCP 服务器分别占了多少。
- 超过近期用量 10% 的行为会单独标出（如上下文太长、缓存没命中），每条附改进建议。
- 按 `d` / `w` 在最近 24 小时和最近 7 天之间切换。
- Session 区块的美元数是本机按 API 价格估算的，对订阅用户只代表「干了多少活」，不是账单。
- **Prompt cache 那行最有用**：显示多少输入走了缓存，没命中时常会给出可能原因。
- 原文建议：拿一个真实任务分别在 Opus 5 和 Opus 5.5 上跑，对比 `/usage`；觉得额度没撑更久，用 `/feedback` 反馈。
