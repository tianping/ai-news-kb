- **原标题**：都2026年了，你跑 Agent 的终端工具落伍了吗
- **分类**：02-tools 工具与产品
- **原文**：https://mp.weixin.qq.com/s/ROmYxOyYJ2rO-DoPCxiVJw

## 概述

终端复用器本是 80 年代的冷门品类（GNU Screen 1987、tmux 2007），解决的是「断网后后台进程不死」。2026 年 AI 编程 Agent 让它翻红：熟手用 Git Worktree 切五六个目录、同时跑五六个 Claude Code / Codex / Gemini CLI，tmux 却分不清窗格里跑的是编辑器还是正在烧 Token 的 Agent。

## tmux 的盲区

- 只把字节流原样画到屏幕，不知道 Agent 状态：1 号卡在数据库迁移确认等你按 y、3 号跑完干等、5 号死循环狂烧 Token——只能人工挨个切窗格排查，人成了串行堵点
- 主 Agent 指挥子 Agent 只能 `send-keys` 硬塞字符串 + `capture-pane` 抓屏幕；对方滚屏或加载动画变了符号，消息静默丢失

## Herdr：草根快跑，「猜屏幕」

- 独立开发者 Ogulcan Celik，2026-03 底建库，7 个月 **4.79 万星**（tmux 攒了 19 年约 5 万）、近 200 万次安装；9 月进 YC，Bessemer 领投 600 万美元种子轮
- Rust 写，单文件约 10MB；保留 `Ctrl+b` 习惯，补鼠标拖拽分屏
- **状态侧边栏**：每个窗格的 Agent 标为 干活 / 卡住等批复 / 刚跑完 / 闲置；有一个等你拍板整个工作区标签就标红；手机连远程终端回个车就能继续
- 识别方法：少数工具接生命周期钩子，多数靠前台进程名 + 扫描终端最后几行文字和光标特征的规则清单，逆向推断 20 多种 Agent 的状态
- **Agent 互调**：Unix Socket 接口 + 专用命令；「架构师 Agent」可切新窗格拉起「测试员 Agent」，再 `herdr agent wait --until blocked` 挂起自己，等子 Agent 跑完或卡住时接管
- 商业：个人运行时永久免费、Apache-2.0；靠团队协作与云端多机管理收费；10 月底发布原生桌面客户端

## Rex（Superlogical）：掀桌重做

- Mitchell Hashimoto（Vagrant、Terraform、Ghostty 作者）新公司 Superlogical，官宣帖 HN 796 分
- 批评复用器套在终端里：每个字节解析两遍（复用器虚拟屏幕算一遍，再转控制字符给外层终端重画）；复用器内置终端内核有时比现代终端**慢 100 倍**；一个客户端往上滚屏，其他连同一会话的窗口跟着乱跳
- 架构：终端模拟器 + 复用器合一的原生桌面应用；服务端只持有 PTY，像 SSH 一样把原始字节流分发给客户端，客户端用 **libghostty** 各自 GPU 渲染
- 压测：单服务端 1 万个活跃终端仅占 **3.8GB** 内存，每个连接端独立滚动
- 内置 Agent Skill：AI 可自己用命令行开标签页、读屏幕，集成 Tailscale 一键连远程服务器
- 商业：闭源，但客户端和服务端永久免费、不强制注册；押注企业生产环境的持久会话层

## OSC 7501：状态上报协议

- Hashimoto 于 **10-06** 发布：程序主动发一行转义序列，向终端汇报 空闲 / 干活 / 等待人工输入 / 完成 / 报错；不支持的老终端会自动忽略，不乱画面
- **10-08 Anthropic 给 Claude Code 合并了 OSC 7501 原生支持**（规范发出仅两天）；Rune、Paneflow 等也跟进，用协议替代屏幕匹配规则
- 影响：各家 Agent 都主动上报状态后，Herdr 靠屏幕抓取攒下的门槛会被抹平——所以 Herdr 做桌面端、Rex 做 Agent Skill，双方互相进入对方领地

## 现实上限

- Reddit tmux 社区案例：同时开 12–15 个 Agent，一天提 20 多个 PR，几天后完全失控，不知道代码改成了什么样，退回手动
- 重度用户经验：一个人能同时盯住**并认真做完代码审查**的并行 Agent 上限基本是 **2–3 个**
- 只跑一两个 Agent → 普通终端分屏够用；长任务动辄一两小时、同时铺开四五个项目 → 才真正需要 Herdr / Rex
