## 概述

X 上近来有很多百万播放的 Claude Opus 5.5 视频作品，例如 kirill 的动效作品集（190 万播放）、Donald 重制的《Claude Pop》MV（390 万播放）。本文讲了 Opus 5.5 做视频的原理，给出一个诺奖科普动画的完整提示词和一个通用提示词模板，并整理了 7 个 GitHub 上的视频提示词和 Skill 项目。

## 原理

Opus 5.5 不是视频模型，它只读文字和图片、输出文字。视频画面全部由它写的代码在浏览器里画出来，每秒 24 帧以上就成为连续画面，再交给其他程序录成 MP4。可以用来给文章做动画讲解、给软件做宣传片，或者把配音稿做成视频；字幕、图形、转场都交给模型。

## 案例提示词：2026 诺贝尔物理学奖科普动画

主题：2026 年诺贝尔物理学奖授予弗朗西斯·哈尔岑（Francis Halzen），表彰他对冰立方中微子天文台的决定性贡献，以及发现具有天体物理起源的高能中微子。

```text
请制作一支中文科普动画，介绍 2026 年诺贝尔物理学奖。
你同时担任科普编导和动画开发者。

【观众与目标】
观众没有大学物理基础。看完应该能解释：
中微子为什么难以探测；冰立方怎样探测中微子；
这项研究为什么能帮助我们了解宇宙。
建议标题：《2026 诺贝尔物理学奖：南极的冰，怎么帮我们观察宇宙？》
时长约 150 秒，中文旁白约 450～550 字，留出观看动画的时间。
横屏 16:9，1920×1080，30 fps，中文旁白与中文字幕。
用 HTML、CSS 和 JavaScript 制作二维示意动画，使用 HyperFrames 渲染。

【事实与资料】
2026 年诺贝尔物理学奖授予弗朗西斯·哈尔岑（Francis Halzen），
表彰他对冰立方中微子天文台的决定性贡献，
以及发现具有天体物理起源的高能中微子。
制作前阅读并核实以下资料：
https://www.kva.se/en/news/the-nobel-prize-in-physics-2026/
https://icecube.wisc.edu/science/icecube/
https://masterclass.icecube.wisc.edu/en/icecube-and-neutrinos/detecting-neutrinos/
获奖者、年份、获奖原因以官方资料为准。
具体数字和历史日期逐项核实，无法核实的内容省略。
体现哈尔岑的构想与领导作用，也说明国际团队的共同贡献。

【分镜安排】
第一幕，约 0～12 秒：从南极地表向下移动，显示冰层中成串的传感器。
开场旁白：「南极的冰层下面，藏着一台用来观察宇宙的仪器。」
第二幕，约 12～25 秒：显示哈尔岑姓名、2026 年诺贝尔物理学奖，
以及冰立方的简化示意图，用两句口语说明获奖原因。
第三幕，约 25～50 秒：用小圆点和轨迹表示中微子穿过物体。
解释中微子是极小、不带电的粒子，很少与物质发生相互作用，
因此难以留下可探测的信号。画面注明：粒子大小和运动速度为示意。
第四幕，约 50～75 秒：用剖面图展示透明的深层冰和光传感器。
解释探测需要很大的体积，透明的冰能让微弱的光传播到传感器。
把传感器画在多根垂直线缆上，体现三维分布，注明数量经过简化。
第五幕，约 75～110 秒：放慢探测过程，按顺序展示：
中微子进入冰层 → 极少数中微子与原子核发生相互作用 → 产生带电粒子
→ 带电粒子运动时产生微弱的切伦科夫光 → 附近的光传感器记录这些光。
每一步配一句短旁白，前一步解释完再出现下一步。
第六幕，约 110～135 秒：让不同位置的传感器依次亮起，
显示记录到的光信号，再用简化箭头展示分析后的来向。
解释科学家根据光到达的位置、时间和强弱，估算中微子的来向与能量。
提一句分析需要排除来自地球大气等背景的干扰。
把画面拉回宇宙，说明高能中微子帮助研究遥远宇宙中的高能过程。
第七幕，约 135～150 秒：重放完整过程：
宇宙中的高能过程 → 中微子 → 冰层中的相互作用 → 光传感器记录 → 科学分析。
用一句自然的旁白收尾，片尾显示简短资料来源。

【画面与讲解】
米白背景、深灰文字，冰层用浅蓝色。
中微子用橙色，带电粒子用绿色，光用蓝色，保留简短图例。
用移动、穿过、局部放大和依次亮起展示过程。
每个镜头只引入一个新概念，复杂步骤放慢。
旁白使用短而完整的句子，术语第一次出现时立即解释，尽量不用公式。
屏幕文字只保留关键词和必要标签，字幕每屏最多两行。
画面与旁白同步，讲到哪个对象，哪个对象才出现或被强调。

【科学准确性】
中微子本身不能发出可见蓝光，蓝光来自产生的带电粒子。
冰立方不能画成拦住所有中微子的网，应显示大量中微子穿过。
动画中的相互作用比例是示意，不能冒充真实概率。
核心探测器埋在南极深层冰中，不能画成地表上的普通光学望远镜。
不能说中微子一定能穿过任何物质，也不能说所有中微子都来自遥远宇宙。
不能把一次探测画成精确锁定某个天体。

【制作与交付】
最终交付实际导出的 MP4。
```

作者的评价：探测原理部分做得很好，橙、绿、蓝三色把中微子、带电粒子和光区分开，观众能跟着画面理解整个过程。

**提示词写法值得借鉴**：给出受众和学习目标、附官方资料链接并要求逐项核实、按秒分镜、规定配色语义，以及列出一节「科学准确性」反例清单，防止动画画错物理过程。

## 通用视频提示词模板

```text
你是一位动态设计师，也是一位创意程序员，擅长用代码做出有设计感的视频。

开工前先问我这几件事，我没给的不要自己编：
1. 主题，以及看完以后希望观众记住的一句话：【你的主题】
2. 时长和画幅：【30】秒，【1920×1080 / 1080×1920 / 1080×1080】，【30 / 60】帧
3. 风格：【像素 / 扁平插画 / 界面动效 / 彩铅手绘 / 复古电视 / 3D】，有参考视频或截图就发给你
4. 配色和字体：【主色 #颜色】，【字体】
5. 声音：【我提供的音乐文件 / 用代码合成配乐】，要不要配音：【要 / 不要】

整片只用一套风格、一套配色，同一个角色或元素在每个镜头里的样子都要一致。
每个镜头只讲一件事，画面上的字少而大，每段文字至少停留 2.5 秒。
动画用缓动或弹簧，不用匀速运动。转场从画面内容里长出来，比如一条线变成下一个场景的地平线，不用默认的淡入淡出。
镜头要跟着内容动，推近、拉远、跟随，让主体在画面里足够大。
禁止：【居中大字加渐变背景的默认风格、所有元素同时淡入、满屏小字、任何看起来像模板的东西，按你的情况补充】

先写分镜表，每个镜头写清楚：
镜头 [N]｜[开始–结束秒]
画面：构图、元素、文字
动作：进场、主要动作、出场
镜头：推、拉、跟随还是固定
声音：这一段的音乐和音效
转场：怎么过渡到下一个镜头
如果有音乐，先分析节拍，镜头切换和关键动作都落在拍子上。

1. 画面用【Canvas 2D / HTML+CSS+SVG / WebGL 着色器 / Three.js / Remotion / HyperFrames】来做，不用外部图片和素材。
2. 页面暴露 window.render(t)，画出第 t 秒。所有画面只由 t 算出来，随机数带固定种子，不用计时器，帧和帧之间不保存状态。
3. 用 Playwright 逐帧调用 render(t) 并截图，再用 ffmpeg 合成 MP4。
4. 配乐和音效用 Python（numpy、scipy）从零合成，每个音效放在画面动作发生的那一帧上；有配音的话，整段合成，不要一句一句拼。
5. 每做完一个镜头，先渲 3 张静帧自己检查：文字有没有溢出、元素有没有重叠、画面够不够满，修好了再做下一个。
- 字体加载完再开始截图，不然前几帧会用默认字体。
- 用了 WebGL 的话，先渲一帧确认着色器真的生效了，再渲整片。
- 你听不到声音，所以要把音频的波形画成图自己检查，确认没有爆音。

先问我问题，然后给我分镜表，等我确认。再渲 3 张关键帧让我看风格，确认后再渲整片。
```

**模板的技术要点**：`window.render(t)` 写成纯函数，画面只由时间 t 决定（随机数固定种子、不用计时器、帧间无状态），这样 Playwright 逐帧截图才能完全复现；配乐用 numpy/scipy 从零合成并卡到帧；每个镜头先渲 3 张静帧自查；模型听不到声音，就把波形画成图来检查爆音。

## 作者观点

- 视频制作需求持续存在：软件介绍新功能、课程讲解知识、品牌为不同渠道准备素材。
- 个人和小团队可以积累自己的动画工程。角色、字幕、镜头和品牌样式做好后，换文案和数据就能继续出片。
- 分工判断：产品界面、动态图表、文字排版等需要精确修改的部分会转向代码动画；人物表演、自然场景、复杂视觉素材仍是视频模型的天下。作者更看好两者结合：视频模型出素材，代码组织图形、字幕和节奏，创作者负责脚本和审片。
- 长期价值在于积累可复用的工程、理解受众、持续交付有用的内容，而不是追求某一次惊艳的生成结果。
