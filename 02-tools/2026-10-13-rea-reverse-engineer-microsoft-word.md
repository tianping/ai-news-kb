## 概述

作者在没有源代码的情况下，用 REA + Codex（GPT-6 Astra，Pro 5X 会员）复刻 Microsoft Word：一句简单提示词出第一版，再迭代 2～3 轮，约消耗 20%～30% 的额度，得到界面近像素级还原、核心功能基本一致的版本。由此提出「AI 复刻钱效比」，并讨论纯软件产品的护城河问题。

## 关键内容

1. **REA 项目现状**
   - Reverse Engineer Anything，约 8.6 万 Star；9 月前已发布但几乎没增长，10 月初约 10 天内从几千涨到 8 万以上，近一个月 99% 的下载量集中在最近一周。
   - 迭代快：5 天发 6 个版本，累计 35 个版本。官方实测案例：Notion（Electron 应用）、DX-Ball（老游戏）。
   - README 宣传语：「看到一个喜欢的功能，就能弄懂它的实现，一直看到二进制层面」。

2. **REA 怎么运作**
   - 本质是 MCP 服务器 + 配套 Agent Skill + 命令行工具。
   - 两块能力：① 自身完成界面解读、图标提取、窗口结构观察等；② 调用 Hopper、Ghidra、IDA 等成熟反编译工具拿接近源码的伪代码（如追踪 SmartArt、查找替换的逻辑）。REA 自动判断哪部分用自带工具、哪部分需反编译。
   - 核心价值：把不同逆向工具的接口统一封装成同一套工具接口，Agent 不必关心底层引擎。
   - 复刻 Word 这类复杂生产级应用，通常仍需 Hopper 等专业反编译工具。

3. **使用方法**
   - 安装：`npx rea-agents setup`，可自动配置 17 个客户端（Claude Code、Claude Desktop、Codex、Cursor、Gemini CLI、Windsurf、Devin、OpenCode、Antigravity、GitHub Copilot CLI、Qwen Code、VS Code、Grok Build 等）。
   - 用自然语言提需求，如「弄清楚备忘录的搜索功能如何实现，列出证据，再在我的项目里做一个类似的功能」；Agent 自主打开目标应用，读程序结构、字符串、符号和资源文件，搜索函数，按需反编译。
   - 细节：用 Claude Code 时，Claude 可能要求使用正版 Hopper；换 Codex 则没有这个要求。

4. **复刻效果**
   - 已实现：界面近 1:1 像素级还原；开始/插入/绘图/设计/布局/引用/邮件/审阅/视图等菜单模块；标题、加粗、下划线、删除线、高亮、批注、排序；图片缩放与对齐；样式与设计模板；插入表格；专注模式与视图切换。
   - 不足：仍有相当一部分功能没完整复刻；交互细节粗糙（如同时选中两行时选区重叠）。原因之一是"AI 爱偷懒"——除非给一套完整的自审开发清单、多轮调子 Agent 检查补齐，否则难以一次做完善。
   - 作者估计基础核心体验复刻约八成，再迭代 10～20 轮可能满足大部分日常使用；目前还不是原生 App。
   - 作者也承认 REA 本身不算革命性技术，大量依赖 Hopper 等工具和模型自身能力。

5. **作者的三点思考**
   - **AI 复刻钱效比**：投入多少 AI 使用成本，能复刻出成熟软件多少有实际价值的功能；Word 开发了 40 多年，现在 Pro 会员 20%～30% 额度就能复刻大部分核心体验（作者也说明，复刻部分功能与开发维护商业软件的成本不能直接比较）。
   - **垃圾 AI 产品会加速淘汰**：很多 AI 产品靠信息差赚钱；产品 100 个功能里真正吸引人的只有两三个，未来可能一个 Skill 就能重新实现。
   - **护城河在哪**：功能（Notion 编辑器）和交互（作者曾用 Opus 5.5 复刻 CleanShot X 截图功能约 95%）都难成壁垒；难复刻的是价值不在代码里的东西——用户网络、独特数据、内容版权、交易体系（能复刻微信聊天界面，复制不了社交关系）。
