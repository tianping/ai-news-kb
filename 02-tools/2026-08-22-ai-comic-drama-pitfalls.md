# 3天做AI漫剧踩了30个坑

> 来源：微信公众号 | 2026-08-22
> 链接：https://mp.weixin.qq.com/s/oaKyFhaw7-Lb2lJQO1GCdg

## 项目概况

- **项目**：《天枢之弈》（古代权谋博弈题材）
- **周期**：3天（8月19日-21日）
- **规格**：81镜 / 7分47秒 / 1088×832 / 24fps
- **角色**：谢蕴、萧桓、赵恪、周崇安、沈老先生、赵恒

## 制作流程

分镜脚本 → 常量图 → 帧图生成 → TTS配音 → 视频生成 → 全片拼接 → 质量抽查 → 帧图修复 → 视频重做 → 最终交付

## 30个坑按环节分类

### 01 帧图生成（3个坑）

**坑1：多人场景"克隆人"**
- AI图像模型倾向复用同一张脸，不主动区分不同个体
- 解法：Prompt显式声明人数，逐角色差异化描述，加 NO duplicates

**坑2：文件名下划线 vs 连字符**
- 帧图文件名 SC1_02.png，脚本用 SC1-02.png 找，对不上
- 解法：项目初始化统一命名规范，脚本加格式兼容逻辑

**坑3：帧图缺了8张**
- 分镜脚本镜头清单提取时漏了几个镜头
- 解法：帧图生成后做完整性校验，逐镜检查文件是否存在

### 02 TTS配音（2个坑）

**坑4：3个音频文件是空的**
- TTS生成过程中断了，脚本没校验输出
- 解法：TTS生成后立即校验文件大小，空文件自动重试

**坑5：两个镜头直接"消失"**
- 镜头清单里被整个遗漏，没帧图没音频没视频
- 解法：镜头清单总镜数必须和分镜脚本核对

### 03 视频生成（5个坑，最严重）

**坑6：81镜视频全部时长不够 💥 最严重**
- 根因：脚本用了固定帧数（81帧=3.38秒），没有根据音频时长动态计算
- 解法：建立帧数映射表，让视频帧数跟着音频时长走
  - ≤3.5秒 → 81帧
  - ≤5.0秒 → 121帧
  - ≤6.7秒 → 161帧
  - ≤10.0秒 → 241帧
  - ≤18.4秒 → 441帧
  - >18.4秒 → 拆分多段链式拼接
- 教训：音频主导原则——视频帧数必须根据音频时长动态计算

**坑7：视频背景"擅自换景"**
- AI在逐帧生成视频时，因为prompt没有约束场景就自己"发挥"了
- 解法：视频prompt必须加场景约束

**坑8：内容审核拦截**
- prompt里用了"predatory menace"被判定为暴力内容
- 解法：暴力/威胁类词汇换温和替代；军警制服改用"深蓝正装+ID工牌"

**坑9：帧图文件损坏**
- 存储过程中截断，视频生成直接报错
- 解法：帧图生成后校验文件完整性

**坑10：修了一轮发色还是不对**
- AI对"灰白发"理解有偏差，一轮修复力度不够
- 解法：二次修复，加强prompt中描述力度

### 04 全片拼接（3个坑）

**坑11：concat文件编码炸了**
- UnicodeEncodeError：concat列表文件非UTF-8、路径用反斜杠、中文路径乱码
- 解法：UTF-8无BOM编码 + 正斜杠路径 + 数字排序

**坑12：单段视频concat不同步**
- concat协议对单段文件处理会重置时间戳
- 解法：只有1段时直接 copy，不走concat

**坑13：视频比音频短的合并**
- 解法：用 `-stream_loop -1 -t {音频时长}` 循环视频流再截断

### 05 质量抽查（3个坑）

**坑14：按平均时长抽帧→镜号全错位**
- 各镜时长不一，平均抽帧时间偏差累积
- 解法：从分段视频按镜号精准抽帧

**坑15：抽查发现背景漂移**
- 同坑7，质量抽查不能只看人物，场景一致性同样要查

**坑16：角色跨镜"变脸"**
- 年龄、胡须理解偏差
- 解法：建立角色常量检查清单，逐角色核对

### 06 角色一致性修复（8个坑，耗时最长）

**坑17：谢蕴的蓝瞳怎么也改不掉** ⭐核心经验
- AI模型对蓝色眼睛有强烈生成倾向（训练数据偏置），img2img无法彻底覆盖
- 解法：放弃img2img，改用text2img从零生成（不传参考图），纯靠文字描述
- 教训：AI顽固特征（发色/瞳色），img2img可能永远改不掉，必须升级为text2img

**坑18：谢蕴的金冠**
- 设定无冠，AI非要给他戴金冠
- 解法：img2img传入原帧图，prompt强调"无冠、束发简单"

**坑19：周崇安5个维度全偏**
- 头发、袍色、体型、脸型、年龄都偏了
- 解法：二轮强约束prompt，加英文关键词

**坑20：萧桓的疤痕被AI"治愈"**
- 小面积特征太容易被忽略
- 解法：prompt重点强调或后期补

**坑21：赵恪的灰白发修了又修**
- 发色修复天然要2-3轮迭代

**坑22：沈老先生直接"返老还童"**
- AI对"老者"理解偏差，年轻了20岁
- 解法：img2img一轮修复

**坑23：变体帧集体漂移**
- 18个B/C变体帧中8个有问题
- 解法：修复策略层层递进，优先用已修复主帧作底图

**坑24：用户说有问题，系统说没问题**
- 解法：以用户反馈为准复核

### 07 视频重做（4个坑）

**坑25：帧图修好了，视频还是旧的**
- 解法：通过帧图文件修改时间与视频生成时间戳对比，定位哪些镜头需重做

**坑26：脚本不支持断点续跑**
- 中途断了就得从头重来
- 解法：检查输出文件是否存在且>200KB，已存在就跳过

**坑27：续跑模式和重做模式冲突**
- 解法：加 force 参数切换两种模式

**坑28：视频生成了，音频忘合了**
- 完整流程：帧图→视频生成→音频合入→场次拼接→全片拼接

### 08 工具与脚本（2个坑）

**坑29：PowerShell把中文写乱了**
- 解法：含中文内容用Python文件操作或Write工具，不用PowerShell echo

**坑30：txt文件首行BOM导致解析失败**
- 解法：读取txt文件用 utf-8-sig 编码

## 3条核心经验

1. **音频主导原则** — 视频帧数必须根据音频时长动态计算，绝不能用固定帧数
2. **AI顽固特征用text2img** — 发色/瞳色等AI顽固倾向，img2img可能改不掉，直接text2img从零生成
3. **帧图修复 ≠ 视频已更新** — 修了帧图还要重做视频、合音频、拼全片，建立帧图-视频对应关系表时刻跟踪

## 其他要点

- 视频prompt不能只写人物动作，必须加场景约束
- 暴力/威胁类词汇换温和替代可绕过审核
- 变体帧必须和主帧一样做角色一致性检查
- 长时间批量任务必须支持断点续跑
