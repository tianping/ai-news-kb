## 概述

作者用 Codex 调度 Blender 建模、再用 Three.js 在浏览器里搭了一个河谷场景。人物可以第三人称进入，跑步、跳跃、到码头开船、拿矿镐采矿、在河边钓鱼。作者只负责给参考图、提要求和验收，建模脚本、网页代码和返修主要由 AI 完成。

| 工具 | 职责 |
|------|------|
| Codex（可换成 WorkBuddy 等 Agent） | 写代码、调度操作 |
| Blender + MCP for Blender | 制作和导出模型 |
| Three.js（TypeScript 项目） | 网页里加载 GLB、显示和运动 |
| Rapier | 物理：人物与坡道/楼梯/码头/船板的接触 |

## 流程

### 1. 打通 Blender MCP

- 装 Blender，把 MCP 开源项目的链接丢给 Agent 安装
- 重启 Codex 和 Blender；插件设置里启用 MCP for Blender；3D 视图按 `N` → MCP 面板，没自动连就点启动服务
- 冒烟测试：让 Codex 建一个立方体、换颜色、保存工程，Blender 里跟着变就算通了

### 2. 参考图 → 拆道具

先用生图做出场景参考图，交给 Codex 识别。**不要一次还原整张图**，模型越多出问题越难定位。拆成 18 件独立道具，分营地、交互物品、木构设施、遗迹四组，每件有自己的尺寸、材质和文件。

第一轮提示词：

> 分析这张参考图，整理其中需要制作的 3D 道具。先不要搭建完整地形。按营地物品、建筑设施、可交互道具和装饰遗迹分类，为每件物体确定大致尺寸、朝向和用途。优先使用 Blender Python 制作结构清楚、方便修改的模型，分别保存，并生成一张道具总览图。

- 木桥：先生成木桩、横梁、踏板，再按下垂曲线排绳索
- 宝箱：箱身和箱盖分开，盖子保留转轴，后面才能开箱

**MCP 断了怎么办**：改成让 Codex 写 Python 脚本，调本地 Blender 后台执行（`blender --background --python ...`）。MCP 不是唯一通道。

### 3. 三种来源混用

- **简单的规则物件**：代码建模
- **复杂造型**：AI 3D 生成（作者用混元 3D，因为可下载模型；也可选 Tripo、Meshy、Hi3D，免费额度和导出条件自查）
- **现成素材**：Fab 的 Quixel Megascans 搜石块、木材、环境道具；这次的小船、旧葫芦、容器是外部 GLB，容器改成了码头边的鱼篓

### 4. 多视角验收、逐个返修

第一轮问题：帐篷支架悬空、吊桥绳子没接到桥头、宝箱铰链不对、石头穿插。让 Codex 给每件道具渲染正面、侧面、斜后方三张图，18 件共 54 张，逐个修：

> 为每个道具生成正面、侧面、斜后方三张检查图，重点检查悬空、穿模、破面、结构连接和模型原点。发现问题后只修复对应模型，并在修改后重新渲染。确保宝箱盖能单独旋转，桥梁和建筑的支撑结构完整。

### 5. 导出 GLB + 优化

- GLB 把模型和材质打包成一个文件
- 减面、整理贴图、压缩：18 件自建道具三角面从约 **46.3 万降到 22.5 万**，GLB 总量约 **30.2 MB**，直接影响浏览器加载是否顺畅

### 6. Three.js 组装场景

- 按参考图布置地形、河道、道路、模型位置
- **摆放的坑**：木箱看着贴地，其实只是原点贴地、底部悬空 → 改成按物体真实包围盒（bounding box）算高度
- 瀑布水面和岩壁接不上，修改后才让上游水流衔接瀑布边缘
- 四套光照：白天、黄昏、蓝调、夜晚（营地灯亮）
- 摄影模式：可调景深和辉光，适合录展示视频

### 7. 角色

- 人物 GLB 原本只有外观、无骨骼无动画；先从约 86 MB 压到约 5.3 MB，做了 23 根骨骼接入网页角色系统
- 第一版动作僵硬、矿镐又大又别扭、跑步像机械狗 → 调手脚关节，引入 **CMU 动作捕捉数据**处理走/跑，握持姿势对齐工具方向
- Rapier 物理负责脚踩实地面
- 最后专门查一轮浏览器适配（不同窗口尺寸布局）

## 体会

- 简单物件代码搭，复杂造型靠生成，高质量素材拿来改，省下的时间用来打磨整体
- 视觉效果只是起点：一旦能自由漫游，悬空、穿模、接缝这类细节问题都会暴露
- 下一步想做：人物遇到 NPC 能自然对话
