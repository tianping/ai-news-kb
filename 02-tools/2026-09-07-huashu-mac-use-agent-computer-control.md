# huashu-mac-use：让任何 Agent 获得接近 GPT-6 的 Computer Use 能力

- **仓库**: [alchaincyf/huashu-mac-use](https://github.com/alchaincyf/huashu-mac-use)
- **来源**: [微信公众号文章](https://mp.weixin.qq.com/s/pgvLMG7pg_1lpPLMN8zbhg)
- **日期**: 2026-09-07
- **定位**: Mac 电脑操控 Skill，任何能读 Skill 的 Agent 都能装——Claude Code、Codex、Kimi Code、Cursor、OpenClaw、豆包工作、千问办公等

## 核心理念

解决白领办公"最后一公里"：除了 Coding，让 Agent 操控电脑和浏览器获取上下文、完成操作闭环。

**第一原则：能不看图就不看图，能不点鼠标就不点鼠标。**

案例：Claude Code 用 33 分钟用 Skill 操控 Blender 从照片重建邮轮模型（400 行参数化脚本，8 轮迭代），以及自建的甜甜圈 3D 场景。

## 三层操控架构

按优先级从高到低，越往上越省事越稳：

1. **命令行/脚本接口**（首选）——Blender 有 Python API 就走脚本，零鼠标点击
2. **辅助功能树（AX Tree）**——读界面元素、写输入
3. **窗口坐标点击**——最后手段
4. **截图识别**——兜底

探测脚本 30 秒摸一遍 App 可用通道，避免硬试浪费时间。

## 三大设计原则

### 1. 先探后做
动手前先跑探测脚本，确定目标 App 的可操控层次。不同内核 App 可操控方式完全不同：
- Chromium 套壳 App（豆包工作、千问办公等）→ 带调试端口，像操网页
- 原生 App（Blender）→ 走 Python 脚本接口
- 后台截图能力与内核无关，与窗口有关

### 2. 读随意，写不抢焦点
- **读操作**（截图、列窗口、读界面）：一律不激活窗口、不切桌面、不动鼠标，被挡窗口也能截
- **写操作**：先尝试直接投事件给进程；不行才借焦点，过四道闸：
  1. 前台是目标窗口
  2. 落点未被其他窗口压着
  3. 2 秒内用户没动键鼠才接管（最多等 15 秒）
  4. 全机同时只允许一个进程借焦点
- 借到焦点时屏幕四角闪取景框（对截图隐身）

### 3. 工具说成功不算数
每步操作必须回读验证：
- 发送键亮没亮、任务进没进列表、文件落没落盘
- 系统自动做前后对比，判不出来标"回去重看"
- 脚本打完 ✅ 也要去目录确认新增文件才认

## 踩坑进化机制

每次收工先问：**这条教训能不能变成工具行为？**
- 能 → 改代码不改文档
- 不能 → 进 references
- 单 App 观察待在 app 档案，两个不同 App 重现过才能升正文
- 坐标、端口、窗口 ID、界面文案是易腐信息，永远不许作为结论写进正文
- 证伪旧结论优先级高于新增

## 部署方式

一句话：把仓库链接丢给任意能读 Skill 的 Agent，说"帮我装这个 skill"即可。

支持：Claude Code、Codex、Kimi Code、Cursor、OpenClaw、WorkBuddy、豆包工作、千问办公、ZCode 等。

## 与 GPT-6 Astra 的关系

Astra 是模型看着屏幕一点一点点（纯视觉路径），huashu-mac-use 走的是"走接口不点鼠标"路线。macOSWorld 论文测过顶级模型纯视觉在 macOS 成功率仅 40%+，所以"按 App 内核选通道""不打扰用户""留证据"这三件事，估计在模型层解决之前还得靠 Skill 层顶一阵。

短期中期有用，长期终将被模型自己的能力完全碾压覆盖。
