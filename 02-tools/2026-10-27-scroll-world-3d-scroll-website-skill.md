## 概述

scroll-world 是一个给 AI 编程助手用的 skill，支持 Codex 和 Claude Code。它按固定流程把一个品牌或业务做成「滚动探索」的视觉网页：访客往下滚，镜头从一个微缩场景飞进去，再穿到下一个场景，比如从果园到加工车间，再到饮品店。

**原理**：先生成带立体空间和镜头运动的视频，再让网页的滚动位置控制视频的播放进度。往下滚，镜头沿预先生成的路线推进；往回滚，画面倒回去。**它不是实时 3D**，不能自由旋转视角。适合做品牌故事、产品发布、场景穿行；要做产品 360° 旋转、换零件这类交互，得另想办法。

仓库提供的是 AI 工作流程、提示模板和网页播放引擎（`scrub-engine.js` + `index-template.html`），**不含现成的视频素材**。素材要靠付费的生成服务来做。

> 原文是根据仓库整理的复现教程，示例品牌「橙屿」是虚构的，作者没有真正跑付费生成流水线。

## 关键流程（8 步）

1. **安装 skill**
   - Codex：`npx skills add oso95/scroll-world -a codex`
   - Claude Code：`/plugin marketplace add oso95/scroll-world`，再 `/plugin install scroll-world@scroll-world`，然后用 `/scroll-world` 调用
   - 完成标准：AI 确认已加载该 skill，并能说出它需要哪些工具、哪些步骤会花钱。
2. **检查依赖、先估费用**：需要 Monid（默认视频生成后端）、Higgsfield（图像生成和备用视频路径）、FFmpeg/ffprobe、Python + Pillow。检查命令：`monid --version`、`monid balance`、`higgsfield workspace list`、`ffmpeg -version`。费用随规格、片长、服务商和重做次数变化，生成前先让 AI 估算，经你确认再动手。
3. **把品牌故事拆成场景**：第一次练手做 3 个就够，例如原料 → 制作 → 产品。写清风格、配色（hex）、镜头路线。**标题、按钮、文案留给网页排版，不要生成进视频**，否则改一个字就得重做素材。
4. **先出静态场景图**：三张图的材质、颜色、光照风格要统一，画面里不要有文字、数字、Logo。确认没问题再批准生成视频，美术方向在这一步就定下来。
5. **生成镜头、检查接缝**：「微缩世界」路线下，3 个场景要 3 段场景内视频，外加 2 段连接视频，共 5 段。连接片段要用前一段**实际视频的末帧**接后一段**实际视频的首帧**，不能用最初的静态图（生成后的视频会有细微偏差）。先检查一处接缝，没问题再做其余的。
6. **接入网页**：用模板配置 `sections`（每节填 still / clip / title / body）和 `connectors`。`diveScroll`、`connScroll`、`scroll`、`linger` 这几个参数调节每段占多少滚动距离、停留多久。文案读不完就调大滚动距离，不必重新生成视频。
7. **本地预览验收**：`python -m http.server 8000 --bind 127.0.0.1`。检查五项：慢慢滚到底、倒着滚回来、快速连续滚、点章节导航、点最终按钮。页面出不来视频时，先在浏览器网络面板查有没有 404、路径大小写对不对，别一上来就全部重新生成。系统开了「减少动态效果」时只显示静态图过渡。
8. **手机版单独决定**：原生手机方案是另一套 9:16 视频链，要额外生成、额外花钱（对应 `stillMobile` / `clipMobile` / `connectorsMobile`）。把桌面视频裁成竖屏不算做完了手机版。

## 备注

- 核心价值是把分镜、画面风格、场景过渡和滚动控制串成一条可复现的流程；网页引擎本身相对简单（滚动驱动视频播放进度）。
- 成本主要花在视频生成服务上，按场景数和重做次数增加。
- 本地预览地址不能拿去分享，要给别人看得部署到静态网站托管。
