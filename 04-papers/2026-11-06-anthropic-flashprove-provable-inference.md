## 要解决的问题

调用大模型 API 时用户只能看到文本输出，无法验证它是否真由服务商宣称的模型生成：服务商可能为省成本路由到便宜模型（「套壳 API」），平台可能篡改 token 流，弱模型可能伪装成强模型规避监管。模型能力普遍提升后，靠输出质量判断模型身份越来越不可靠。

## 方案：离线承诺 + 在线证明

1. **离线承诺**：服务商用单张 H100 为模型权重生成公开的密码学承诺，约 **39 分钟**，一份承诺可支撑约 **1600 万次**请求；承诺不可逆，无法反推权重，保护知识产权
2. **在线证明**：每次推理后为生成的 token 序列输出一份证明；用户拿到 承诺 + 提示词 + 输出 + 证明，用**普通 CPU** 即可核验，不接触权重、不暴露中间计算，也看不到 MoE 激活了哪些专家

技术栈：zkSNARK（与以太坊二层同源）；BLAKE2 哈希（不依赖椭圆曲线，理论上抗量子）；单次推理约 2000 个 sumcheck 子协议。

## 实测（Llama 4 Maverick，400B 参数 MoE，4-bit 量化，激活约 17B）

| 指标 | 数值 |
|------|------|
| 证明生成吞吐（单 H100） | 约 **110 tokens/s** |
| 证明大小（1024 token 请求） | 约 **19 MB** |
| 验证耗时（24 线程 CPU） | 约 **17 秒** |
| 离线承诺 | 约 39 分钟，支撑约 1600 万次请求 |
| 证明阶段 GPU 时间 vs vLLM 推理 | 约 **70–95 倍** |

- 证明工作量与**激活参数**挂钩而非总参数——这是单卡能跑的关键
- 232GB 量化权重远超 80GB 显存：权重驻留主机内存、**流式分段**送入 GPU 计算编码后立即释放——单卡可行，但也是 GPU 时间膨胀 70–95 倍的原因

## 局限（README 明确标为 research artifact、not maintained）

- **事后证明**：生成完成后再并行出证明，只能事后检测，不能在回复发出前实时拦截
- **上下文最多 1024 token**，与 Agent 场景常见的数十万 token 差距巨大
- **采样不一致风险**：证明的是整数模型的**贪心解码**结果；浮点实现或温度采样的输出可能在某些位置与被证明结果不一致
- **不隐藏架构**：利用 MoE 结构提效，保持专家选择私密不是设计目标
- **验证链待审计**：Lean 协议、论文与 C++ 快速验证器之间的形式化对应仍需人工审计；侧信道风险不在发布范围内

## 代码构成

- 约 **95.2%（近 400MB）是 Lean 4 写的数学形式化证明**，C++/Python/CUDA 实现占比很低
- 配套 114 页协议论文 + 23 页技术报告
- 同时开源日常用的 C++ 快速验证器和提供形式化保证的 Lean 验证器
- Anthropic 称大量代码、论文初稿和测试由 **Claude 参与完成**

## 意义

不是即插即用的商用组件，而是指明路径：在模型评测、第三方路由、合规审计中，把「信任服务商声明」换成「验证可检查的密码学证明」。

## 事实核对（2026-11-06）

与 Anthropic 官方研究页（11-03）、MarkTechPost（11-03）、technology.org（11-05）一致：Llama 4 Maverick、单 H100 约 110 tok/s、1024 token 证明约 19 MB、24 核 CPU 验证 17 秒。shattered.io 标题给出开销约 72 倍，落在文章所说 70–95 倍范围内。

## 备注

- 公众号标题「17 秒识破套壳 API」有夸张：目前仅 1024 token 上下文、贪心解码、研究原型，离真正用于检测商用 API 还很远，且需要服务商**主动配合**做承诺和出证明——它防的是服务商作弊，前提是服务商愿意接入
