## 一句话

Lean 不是靠"理解"或"直觉"做证明，而是用依赖类型论把数学推理编码成代码：**命题是类型，证明是这个类型的一个对象**；证明写成什么样都行，最后都要变成证明项，交给一个极小的内核逐条检查。

## 核心观念

### 1. Lean 首先是一门语言
- 正式身份：交互式定理证明器（ITP），底座是依赖类型论 / 依赖 λ 演算
- 能写普通程序（`def double (n : Nat) : Nat := n + n`），也能定义自然数、群、拓扑空间并证明命题
- 类型 = 契约：`ℕ → ℕ` 必须返回自然数，返回字符串就被拒

### 2. Curry–Howard 对应：命题 = 类型
- `P → Q` 既是蕴含，也是函数类型：输入 P 的证明，输出 Q 的证明
- 三段论 `(P → Q) → (Q → R) → (P → R)` 的证明就是函数复合 `fun hp => hqr (hpq hp)`——不是对证明的描述，而是证明本身

```lean
theorem and_swap (P Q : Prop) : P ∧ Q → Q ∧ P :=
  fun h => And.intro h.right h.left
```
Lean 并没有"懂得合取交换律"，只是检查 `h.right : Q`、`h.left : P`、组装后类型是否为 `Q ∧ P`。

### 3. Prop 与各逻辑连接词怎么"交货"
| 命题 | 要交出的东西 |
|---|---|
| `P ∧ Q` | P 的证明 + Q 的证明 |
| `P ∨ Q` | 任一边的证明 |
| `P → Q` | 把 P 的证明变成 Q 的证明的函数 |
| `∃ x, R x` | 一个具体的 x + R x 的证明 |
| `∀ x, P x` | 对任意 x 返回 P x 证明的函数 |

### 4. 依赖类型：类型携带性质
- `Vec α n`：长度恰好为 n 的向量，`Vec Nat 3` 与 `Vec Nat 5` 是不同类型，错误在运行前就被拦住
- 正整数要大于 0、矩阵行列数确定、群要满足公理——纸笔里藏在上下文的条件，在 Lean 里直接进类型

### 5. 归纳 = 递归程序
```lean
theorem add_zero (n : Nat) : n + 0 = n := by
  induction n with
  | zero => rfl
  | succ n ih => simp [Nat.add, ih]
```
自然数由 0 和后继两种构造生成，所以归纳就是分两种情况；`ih` 就是归纳假设。列表、树、表达式同理：有什么结构，就沿什么结构证明。

### 6. rfl 不是"我宣布相等"
`(fun x => x + 1) 2 = 3` 用 `rfl`：Lean 自己把左边算成 3，两边是同一个表达式才承认——**计算本身参与证明**，它不信"显然"。

### 7. 战术（tactic）不是最终证明
- `intro / constructor / exact / induction / rw / have / simp / ring / linarith / norm_num / omega / aesop` 是"生成证明的指令"
- 交互式：Lean 实时显示还没填的目标（goal）
- 流水线：**Parser → Elaborator（补隐式参数、类型推断、把 tactic 展开成证明项）→ Kernel（唯一裁判）**
- 内核检查 `Γ ⊢ t : P`；遵循 **de Bruijn 准则**：内核极小，只要内核没错证明就可靠

### 8. 自动化是助教，内核是裁判
自动化工具可以复杂甚至有 bug，但只能提交证明项、不能越过内核宣布定理成立。可信性不建立在"自动化不出错"上，而建立在"错误结果包装不成合法证明"上。

## 边界与注意

- **证明 ≠ 测试**：测试只覆盖有限样本；定理里的 n 是任意自然数，成本也因此更高
- **Lean 能可靠地证明一个错误建模的命题**：定义写宽了、现实条件漏了，Lean 不会帮你补。它保证"推理无跳跃"，不保证"定义贴合现实"——形式化最大收获常是发现自己原来没说清要证什么
- **sorry 不是证明**：暂借的通行证，会留警告；依赖它的定理可信度都受影响（所以"零 sorry"是形式化项目的硬指标）

## Mathlib 与协作

- 群/环/域、极限、连续、积分等都已在 Mathlib 里，后来者直接调用
- 形式化数学越来越像软件工程：定义复用、接口稳定、依赖透明、改基础定义会波及全局
- 陶哲轩用 **blueprint（蓝图）** 可视化定理依赖：哪些已证、哪些待证，兼做进度表与协作路线图

## 分工：数学家 / AI / Lean

- **数学家**：选问题、设计定义、提猜想、判断假设合理性、解释意义
- **AI**：证明搜索、在库里找定理、猜下一步战术、自动形式化（自然语言 → Lean）；AlphaProof 以 Lean 为验证后端做 IMO 题
- **Lean**：检查候选证明是否真的成立
- 一句话："**AI 负责猜，Lean 负责查**"
