## 概述

耶鲁大学管理学院会计学副教授 **John Barrios** 公开了博士生课程《Claude Code for Accounting Research》，讲怎样把 AI（Claude Code）放进会计 / 经济学实证研究的各个环节。文章挑出几种做法，配案例讲它们解决什么问题，并用 Codex 演示怎样迁移到自己的研究。共同思路：**让 AI 先完成一项具体工作，再根据它交出的东西检查、追问、调整；反复用的步骤整理成 Skill。**

## 关键内容

### 01 提出具体任务
- 笼统请求（「看看这份 Compustat 数据，分析一下杠杆率」）没说怎么算、按什么汇总、交付什么，AI 只能猜
- 具体版本：「读取 funda_1990_2023.csv，逐家企业、逐年计算长期债务占总资产的比例；对极端值按第 1 和第 99 百分位缩尾，再按行业和年份计算均值。保存行业年度汇总表和各行业的趋势图。」
- 要点：交代**原始数据的记录单位**、计算方式、汇总口径和交付文件；让 AI「先告诉我你准备用哪些列和处理步骤」
- 好处：人也能按步骤逐项检查结果，能从图中一个点追到企业底表

### 02 边分析边记录
- 要求分别保存清洗、计算、绘图脚本；**每次筛选记录前后样本量和原因**；保存绘图用的汇总数据
- 某年样本突然减少时，可直接查是哪一步筛选造成的
- 案例：研发强度计算从 37,498 条降到 15,232 条，主要是剔除约 2 万条缺研发费用 / 资产的记录 → 下一步判断是企业披露不规范还是字段提取代码有问题

### 03 从失败中追问
- 用 Claude Code 提取美国上市公司年报（10-K）的风险因素章节，并生成**质量报告**（哪些成功、哪些失败）
- 60 份年报 4 份失败，追问「为什么缺了这 4 份？」→ 原因：程序定位到的是**目录**里的章节标题，不是正文标题
- 做法：保留异常名单和原文，针对具体文件追查，修正规则后重跑、再看质量报告；明确要求「区分目录和正文，没找到就说明原因，不要把目录当正文」

### 04 重复任务做成 Skill
- 先用少量文件跑通，再把固定步骤与每次变化的输入分开，明确输入、输出、步骤，换一批材料验证能否复用
- 示例指令：「把这次年报提取过程整理成一个 Skill。以后由我提供企业名单和年份，输出原文、提取文本和异常报告。」→ 生成 `annual-report-check`

### 05 让 AI 指出论证问题（只批注不改写）
- 指令：「请阅读这段研究设计，指出论证不清楚或需要补充依据的位置，用批注解释问题。保留原文，不要直接改写。」
- 用**独立会话**做审阅：稿件放单独目录，审阅报告单独保存，作者逐条处理
- 作者逐条判断：是关键假设没解释，还是数据和结论之间少了一步论证
- 示例（政策对企业研发的影响）：检查比较对象的选择和政策影响的识别方式；批注指出了样本范围、时间口径、缺失处理等问题

### 06 推荐 Skill：econ-skills / audit-econ
- 检查经济学研究里的数学推导、计量方法、代码和数据
- 合集还有论文阅读、文献综述、科研绘图等 Skill
- https://github.com/zbsaygin/econ-skills/tree/main/audit-econ

### 尾声
Barrios 的问题：当 AI 能更快帮我们产出图表和论文时，研究者怎样继续积累自己的理解与判断？

## 影响 / 备注
- 这套方法对生信分析同样适用：具体化任务（数据单位 + 处理 + 交付物）、记录每步样本变化、保留失败名单追问原因、反复流程做成 Skill、独立会话只批注不改写
